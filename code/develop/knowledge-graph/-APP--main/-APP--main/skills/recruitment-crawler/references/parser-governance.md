# 解析与发布治理

## 证据优先

同一平台、关键词和质量指标连续 3 天异常，或出现 `card_parse_fallback` 时，进入人工修复流程：

1. 读取最近 2 至 3 次日志，确认是重复症状而非一次性网络波动。
2. 选择受影响组合的最新 HTML 快照；快照才是选择器修改依据。
3. 回放当前解析器，记录岗位数以及链接、公司、薪资、地点覆盖率。
4. 优先使用稳定 `data-*`、嵌入分析 JSON 和语义类名；禁止依赖构建哈希类名。
5. 每张卡片内独立绑定字段。字段不确定时留空，禁止跨卡拼接。
6. 运行全套离线验证，再回放新旧快照。只有覆盖率恢复且岗位数合理时才接受修改。

`no_relevant_jobs` 和 `possible_truncation` 是信息型指标，不触发连续告警修复线；真正抽不出标题的解析故障使用 `parsed_jobs` 等可行动指标。

## 平台规则

- 猎聘：以 `job-card-pc-container` 卡片和 `data-nick` 锚为主；构建哈希类名会漂移，不得使用。
- 前程无忧：以 `joblist-item` 卡片和嵌入 `sensorsdata` JSON 为主；排除首页推荐的 `s=pchome_*` 链接。
- 智联招聘：以 `joblist-box__item` 分卡；标题 `jobinfo__name`、薪资 `jobinfo__salary`、地点 `jobinfo__other-info-location-image` 后首个 span；公司按 `companyinfo__name` class token 提取，较长名称会同时带 `companyinfo__name-short`，不能要求 class 值完全相等。明确“找不到职位”才算真实零结果。
- 国聘：以 `job-card` 分卡，读取 `job-name`、`job-district`、`job-salary` 和 `company-name`。岗位详情由 React 路由生成，卡片没有详情链接时只使用真实公司页并标注“查看公司页”；禁止把导航、客服或文档链接当岗位链接。

分页必须遵循页面证据并在相关性过滤前判重：

- 猎聘使用已验证的 `currentPage` 和 `pageSize=40`
- 智联跟随页面真实下一页 href
- 国聘只点击未禁用的 React 下一页
- 前程无忧只跟随真实下一页锚，不猜测 `pageNum`

重复页、下一页无变化或达到 `max_pages_per_query` 时停止，并保留 `possible_truncation` 说明。

## 相关性与去重

- `classify_relevance` 产生 `core`、`industry`、`weak` 或 `irrelevant`；`is_relevant_job_title` 决定准入。
- “驾驶员”必须与无人机语境共现。
- 普通飞行器、航空器、适航、飞控和纯“航空”只在 eVTOL/低空经济宽口径下保留待复核。
- CAAC 关键词仍必须保持无人机方向，普通民航机务、座椅、放行岗位不得放行。
- 先按稳定岗位 ID 合并，再按公司、归一化标题和城市文本合并。
- 公司缺失时禁止仅用标题和城市合并，改用平台、标题、城市和薪资的窄键。
- URL 签名不含 `www.` 或平台集合；文本签名把地点归一到城市级。
- 同日重跑不增加签名 `seen_dates` 天数。主签名损坏时只回退到校验通过的 `.bak`；主备都损坏时禁止发布。

## 质量门禁

- 明确空结果页是合法零；有标题但零相关是 `no_relevant_jobs`；有卡片但抽不出标题是解析故障。
- 浏览器不可用、页面失败/拦截、网络错误页、空正文加空 HTML 或重试耗尽必须抛抓取错误。
- 失败组合是 `-1`，真实空结果是 `0`。只有失败/零且没有任何正结果、任一平台全关键词失败，或失败比例达到阈值时拒绝发布。
- 检查公司、薪资、地点、行动链接的缺失率，非法字段，搜索页兜底，14 次成功历史中位数突降和分页截断。
- 非法字段在业务对象进入去重和签名前清空；原值仅保留在受限质量样本中。

## 发布事务

发布顺序固定为：

1. 创建飞书文档
2. 授予成员权限
3. 发送群消息并取得 `message_id`
4. 原子保存签名
5. 追加成功历史

超时或 EOF 可能已经在服务端建档，属于模糊失败，禁止自动重试。恢复时只复用已经明确取得的文档和授权回执。“权限已存在”可视为满足；群消息已送达但本地收尾失败记为 `delivered_degraded` 并阻断自动重复消息。

runner 使用 `umask 077`，目录为 `0700`，日志、状态和 PID 为 `0600`。通知只有在 CLI 返回码为 0、JSON 顶层 `ok=true` 且递归取得 `message_id` 时才算成功。
