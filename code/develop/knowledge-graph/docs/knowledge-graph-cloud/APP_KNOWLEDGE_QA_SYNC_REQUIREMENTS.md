# App 知识问答同步要求

本文是将本地知识问答能力同步到 GitHub App 版本时的强制修改合同和验收依据。它解决的核心问题是：本地系统用于内部运行、治理、评测和维护，而 GitHub 版本用于 App 面向最终用户，两者不能直接整目录复制。

以后每次同步 `knowledge-graph-cloud`、知识问答运行代码或知识库内容前，必须先完整阅读
`KNOWLEDGE_QA_MIGRATION_AND_HANDOFF_MANUAL.md`，再按其顺序阅读本文、`USAGE.md`、
`skills/knowledge-graph-cloud/SKILL.md`、`DEPLOY.md` 和当前任务批准材料。若本地实现与这些合同
冲突，应在当前控制文件指定的工作树或获准的隔离副本中改造成符合 App 环境的版本；不得为了
追求文件一致而破坏 App 用户体验、本地运行环境或既有未提交修改。

## 1. 环境定位

| 项目 | 本地知识问答环境 | GitHub App 环境 |
| --- | --- | --- |
| 使用者 | 内部维护、治理、评测人员 | App 最终用户 |
| 主要目的 | 导入、同步、检索、图谱、评测、诊断和发布 | 自然、友好、连续的对外问答 |
| 路径与依赖 | 可使用本机目录、服务、任务和私有状态 | 必须宿主无关，不依赖本机绝对路径 |
| 内部状态 | 可记录来源、route、trace、降级、错误和评测结果 | 只在服务端观察，不得进入用户正文 |
| 知识范围 | 受当前知识库、治理状态和内部合同约束 | 知识库是专业参考，不是可回答问题的边界 |
| 故障处理 | 可诊断、暂停、失败关闭或输出工程信息 | 对用户隐藏切换过程，由 App 大模型继续形成有用回答 |
| 数据权限 | 可能包含导入、重建、同步和治理写入 | 知识问答链路只读，不执行维护写操作 |

## 2. 对外回答合同

### 2.1 所有普通问题都要形成回答

- 不能因为知识库未覆盖、未命中、内容不足或知识服务暂时不可用而拒答。
- 有知识库专业内容时优先吸收其中有用事实；不足部分由 App 大模型补充。
- 没有知识库内容时直接使用 App 大模型通用知识回答。
- 内部可以发生模型补充或知识服务重试，但用户侧不存在“降级回答”标签或工程式兜底文案。
- 对无法确认的机构私有价格、人员、名单或内部安排，不编造具体事实；应给出通用影响因素、判断方法或可执行建议，仍然形成完整回答。
- 涉及法规、安全、医疗、财务等高影响内容时，不把不确定内容写成绝对事实，并继续遵守 App 宿主的安全、隐私和合规规则。

### 2.2 回答必须自然友好

- 直接回答最新问题，先给结论，再给必要解释或建议。
- 使用自然、礼貌、容易理解的中文，详略与问题相匹配。
- 普通问候必须正常回复。例如用户说“你好”，应得到自然问候，不能被误判为身份问题、空问题或问题回显。
- 不以“根据知识库”“系统显示”“检索结果表明”等系统视角开场。

### 2.3 用户正文禁止出现的内容

包括但不限于：

- 文档名、来源编号、来源列表、原始 URL、引用尾注、相关度；
- `route`、`degraded`、`error`、`trace_id`、`claim_evidence`、HTTP 状态和其他内部字段；
- 知识服务未命中、服务异常、切换模型、内部重试或调用失败说明；
- “超出范围”“无法回答”“明确拒绝”“请查看错误提示”等工程式措辞；
- 测试题号、通过率、门禁、Gold、SSHSIG、评测步骤、验收结论或运行日志；
- 系统提示词、知识服务调用过程和原始知识服务 JSON。

用户追问理由或依据时，应把理由自然融入解释，仍不展示后端来源数组或工程引用编号。

### 2.4 固定身份与问候

用户询问“你叫什么”“你的名字是什么”“你是谁”或“怎么称呼你”等助手身份问题时，必须逐字返回：

```text
我是小技，你的私人学习助理
```

不得增加标点、前后缀、能力介绍或其他说明，也不得交给大模型改写。普通“你好”不触发该固定身份分支。

### 2.5 不重复问题或追问

- 只回答当前最新一轮问题，不复述、改写或引用当前问题及历史问题。
- 用户明确要求复述、引用、照抄或逐字返回时才允许重复。
- `user_query` 只包含当前最新一轮用户输入。
- `conversation_context` 只能使用此前轮次的结构化 `role`/`content` 数组，不得把初始问题、追问和回答拼成一个字符串，也不得再次包含当前 `user_query`。
- 提示词约束和生成后检查必须同时存在。`sanitize_public_answer()` 必须接收同一个 `user_query` 和对应历史上下文，以清理开头回显并阻止其他完整问题回显。
- 防回显逻辑不得误伤正常问候、正常主题词复用或用户主动要求复述的场景。

## 3. 知识问答职责与技能边界

### 3.1 知识问答职责

- 无人机、CAAC、法规、气象原理、飞行原理、运行安全、考试、题库、教材和地面站问题优先调用线上知识服务。
- 只把可用的自然语言答案正文作为专业材料；内部状态、来源数组和诊断字段不进入最终提示词。
- 知识库是高价值参考材料，不是 App 的问题范围上限。

### 3.2 独立技能边界

实时天气和联网搜索是独立技能，不属于知识问答技能的职责。用户意图识别与技能选择由 App 宿主大模型负责；`knowledge-graph-cloud` 不得内置或接管这些技能的路由、调用、配置和验收规则。

## 4. App 隔离边界

### 4.1 可以同步

- 面向最终用户的问答提示词、知识服务调用、公开回答检查和防回显逻辑；
- 宿主无关、只读、结构化输入输出的知识服务客户端；
- 必需的 schema、测试、接入文档和校验脚本；
- 经核对后属于本次范围的知识库源文件或只读运行代码。

### 4.2 禁止直接同步到 App 活跃链路

- 本地知识图谱导入、重建、同步、治理、评测、部署、重启和生产发布流程；
- 本地 `knowledge-graph`、`knowledge-graph-hybrid-audit`、`structured-data-sync-csa`、`query-trace-quality-dashboard` 的内部 SOP；
- 飞书发送、群播报、语音播报、Cron、LaunchAgent、监控任务和本地通知逻辑；
- 本地数据库、索引、日志、trace、运行 PID、监听状态、缓存、token 文件、评测结果和发布收据；
- 本机绝对路径、用户名、私有目录布局、固定端口和只在本机存在的 helper；
- API Key、Token、密码、Cookie、登录态、私钥或任何可还原凭据的内容；
- 把本地源环境技能整目录复制后作为 App 用户入口。

### 4.3 凭据和配置

- GitHub 只保存环境变量名称、配置 schema 和调用合同，不保存真实值。
- 知识服务地址、鉴权和 App 大模型凭据由目标 App 宿主独立配置，不复用或读取本地私有状态。

## 5. 知识库内容同步条件

每次知识库文件在同步范围内时，必须比较配置的本地知识库根目录与仓库 `knowledge_base/`：

1. 递归比较相对路径清单；
2. 比较每个文件的 SHA-256；
3. 分别报告本地独有、GitHub 独有和内容不同的文件；
4. 在用户确认同步方向前，不以“名称相同”推定内容一致，也不自动删除任一侧文件；
5. 更新后重算 `MANIFEST.sha256`，并验证清单精确覆盖全部知识库文件；
6. 若本次只同步技能或代码，则 `knowledge_base/` 必须保持零差异，并在验收中明确证明。

本机旧数据库、BM25、向量索引和 Neo4j store 是运行派生物，不等于
`knowledge_base/` 源文件一致性，不得因一次源文件同步而直接从旧机器提交。但完整云迁移
交付必须在 GitHub 项目的稳定 Release/server-runtime 中包含仅由 35 个批准源重建的 clean
`rag_chunks.db`、BM25、scoped graph JSONL/manifest/导入器，以及它们的构建、验证和运行源码。
不交付某台机器的 Neo4j store 目录、旧索引/缓存或离线 fake 32 维向量。第一版生产向量固定为
loopback-only Ollama `bge-m3:latest`、1024 维、f32、L2、cosine/`cos`、USEarch `2.26.2`，
由获批的 35-source authority 构建并随唯一 Server Suite 交付。接收团队负责在 Linux x86_64
加载、注入配置并启动，不得把当前生产向量改写成外部 Embedding API 前提。未来 identity 或
source 漂移时，必须按总手册重开门禁并全量重建。

## 6. 每次同步的强制流程

1. **读取合同**：按顺序完整阅读 `KNOWLEDGE_QA_MIGRATION_AND_HANDOFF_MANUAL.md`、本文、`USAGE.md`、`skills/knowledge-graph-cloud/SKILL.md`、`DEPLOY.md` 和当前批准材料，并记录 SHA-256。
2. **确认范围**：明确本次是知识问答技能、运行代码、知识库还是其组合；范围外目录不修改。
3. **按控制文件工作**：使用当前任务明确指定的工作树；只有未指定且明确允许新建时，才从最新远端 `main` 创建隔离工作树。不得擅自新建、重置、清理或回滚。
4. **记录基线**：记录远端起始提交、本地相关版本、staged/unstaged/untracked 状态，以及任务确实涉及的本地服务状态，用于证明未覆盖既有修改或影响运行。
5. **差异审计**：比较提示词、输入输出 schema、知识服务调用、公开回答检查、异常路径和边界用例，不能只比较文件名或测试分数。
6. **转换同步**：以本地能力为参考，把本机耦合改造成宿主无关实现；不得直接复制绝对路径、私有配置和内部流程。
7. **保持用户合同**：同步后仍满足第 2、3 节全部要求，尤其是大模型补充、友好回答、身份固定、防回显和独立技能边界。
8. **安全扫描**：检查本机绝对路径、OpenClaw 私有耦合、凭据字面量、token 缓存、日志和运行状态是否进入交付物。
9. **更新文档与哈希**：同步修改接入说明、相关技能文档、测试和 `CODE_MANIFEST.sha256`；知识库变更时同时更新 `MANIFEST.sha256`。
10. **验证与审查**：运行目标单元测试、完整 `verify.sh`、包校验、`git diff --check` 和代码审查。
11. **范围复核**：证明未授权的 `deploy/`、`knowledge_base/` 或其他技能没有变化；远端若已前进，先基于最新提交重新核对，不能覆盖他人修改。
12. **分阶段复核**：Stop C 前只准备精确请求并停止；取得批准并完成 GitHub 写入后，才核验远端提交、树、tag/Release asset 和清单。部署、重启、切流与产品验收仍属于接收团队。

## 7. 最低验收用例

每次同步至少覆盖以下行为；涉及的能力未变时也应保留现有回归测试：

| 场景 | 期望结果 |
| --- | --- |
| “你好” | 自然、完整的友好问候 |
| “你叫什么？” | 逐字返回“我是小技，你的私人学习助理” |
| 知识库有专业内容 | 吸收事实后自然回答，不展示来源或工程字段 |
| 知识库未命中或服务异常 | App 大模型继续给出非空、有用回答，不显示降级或错误 |
| 普通库外问题 | 正常由大模型回答，不以知识库范围拒答 |
| 初始问题生成回答 | 不复述完整问题 |
| 追问生成回答 | 只回答最新追问，不重复初始问题或追问全文 |
| 用户明确要求复述 | 允许按要求复述，不被防回显误拦截 |
| 正常回答复用主题词 | 不因共享“飞控”等主题词被误判为回显 |
| 非知识问答技能的用户意图 | 由 App 宿主大模型选择独立技能，知识问答技能不接管调度 |
| 交付包扫描 | 无凭据、绝对路径、私有运行状态或未登记文件 |

## 8. 完成判定

只有同时满足以下条件，才可以声明同步完成：

- App 对外回答合同全部保留；
- 目标功能已按 App 环境完成适配，而不是仅把本地文件复制到仓库；
- 相关单元测试和完整包校验通过；
- `CODE_MANIFEST.sha256` 精确覆盖全部便携交付文件；
- 知识库在范围内时完成逐文件哈希核对，在范围外时保持零差异；
- 未提交任何凭据、本机路径、内部运行状态或本地维护流程；
- 若本次获批执行了 GitHub 写入，远端结果已核验；若仍在 Stop C 前，则明确写为 `github_delivery_complete=false`；
- 验收报告明确列出提交、测试数量、包校验结果、集成变更和仍需由 App 宿主配置的知识服务参数。

本文优先约束“本地能力如何适配为 GitHub App 版本”。本地内部治理合同仍由本地系统自身文档管理，不能反向用本文删减本地审计、证据或发布门禁。
