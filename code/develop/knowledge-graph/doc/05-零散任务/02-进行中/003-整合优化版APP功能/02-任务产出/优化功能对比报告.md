# 优化功能对比报告

## 1. 对比范围与结论

- 目标基线：`E:/huiyitechworkspace/knowledge-graph`
- 参考源：`E:/huiyitechworkspace/knowledge-graph/-APP--main/-APP--main`
- 结论：不做目录覆盖。前端共同页面无内容差异且参考源静态包不完整；后端仅整合与目标现有问答链兼容的请求信封、确定性检索计划、响应治理/降级契约和客户端 POST 兼容。
- 目标现有导入、Cypher、2D/3D CRUD、Windows 启动链、Neo4j/SQLite 数据与配置均保留。

下表中标注的目标 `server.py` 行号来自实施前信息收集快照；实施后的实际入口与行号记录在 `整合实施记录.md`。

## 3. 分类清单

### 整合

1. `POST /api/ask` JSON 信封：`user_query` 必填，可选 `risk_level`、`timeliness`、`allowed_sources`；未知字段和歧义参数返回结构化 400。
2. 保留 GET `/api/ask?q=...`，通过相同请求信封归一化，确保旧页面和调用方不回退。
3. 为每次请求生成稳定指纹和确定性检索计划；计划只声明目标实际启用的 `csa`、`bm25`、`dense`、`neo4j`、`web` 通道。
4. 回答来源按 `chunk_id` 去重，文档证据只公开仍有响应来源支撑的条目；无来源事实答案失败关闭。
5. 成功响应同时返回顶层和 `stats` 内的 `degraded`、`degraded_reasons`，并返回请求信封、检索计划及治理字段。
6. `kg_query.py` 使用 POST 优先，仅遇到 405 才回退 GET；保留旧响应兼容，并区分服务不可用与查询失败。

### 保留

1. 目标全部前端文件及 2D/3D 本地静态依赖。
2. 文件导入、图谱统计/查询、展示、Cypher、实体/边/3D 节点 CRUD 与导出路由。
3. 目标 Neo4j、SQLite、索引、日志、模型配置、密码文件位置和 Windows 启动方式。
4. 目标现有混合路由、外部补全、CAAC 实操评分保护和远程 shadow 行为。

### 暂缓或不整合

1. 参考源完整 `answer_policy.py` 及其法规、题库、claim-evidence、模型恢复闭包：依赖目标缺失模块和不同数据 schema，整文件复制风险不可控。
2. `query_trace.py` hash-chain/轮转：直接依赖 Unix `fcntl`，不满足 Windows 兼容。
3. 参考源只读路由裁剪：会删除目标明确要求保留的管理能力。
4. Waitress、Host 白名单、收窄 CORS、仅本机绑定和全环境变量密钥：均改变现有本机访问/启动契约，本任务不顺带迁移。
5. 参考源数据库、索引、日志、缓存、备份、凭据和静态包：不复制、不覆盖。

## 4. 回退条件核对

- 新增模块不读取数据库或索引 schema，不依赖 `fcntl`，无需删除目标写接口，也不覆盖配置与数据。
- 因而请求边界、规划、通用治理和客户端兼容可继续局部整合；迁移专用完整治理链及部署安全链按上述原因止损暂缓。
