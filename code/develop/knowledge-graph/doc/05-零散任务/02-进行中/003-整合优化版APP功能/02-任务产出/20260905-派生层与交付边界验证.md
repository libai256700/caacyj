# 2026-09-05 派生层与交付边界验证

## 1. 权威源到派生层链路

交接手册规定的唯一链路为：

```text
approved knowledge_base/ + source manifest
  -> clean rag_chunks.db (authority: chunk_id -> text)
  -> BM25 index
  -> loopback-only Ollama bge-m3:latest (1024-d, f32, L2/cos, USEarch 2.26.2)
     -> chunk vector + entity vector 双索引
  -> portable scoped graph JSONL + graph manifest/importer
  -> offline gates
  -> sealed candidate
  -> manifest / SBOM / DLP / tests / SHA256SUMS evidence
```

源 allowlist、正文、切分、schema 或 identity 任一变化，都必须从新的权威源全量重建受影响派生层；不能手工修改 Release 内 SQLite、BM25、向量或 Neo4j 数据，也不能以旧机器 Neo4j store 代替 portable scoped graph。

## 3. App 与服务端包边界

- `knowledge-graph-cloud-app-upload.zip` 仅提供一个 `knowledge-graph-cloud/` 技能根、`SKILL.md`、契约、宿主接入说明、客户端、回答适配器和测试；App 只调用知识服务并由宿主生成最终回答。
- `knowledge-qa-final-delivery-linux-x86_64-20260905-r2.zip` 才包含服务端运行代码、权威 SQLite、BM25、双 USEarch 索引、portable scoped graph、Neo4j importer、operator companion、SBOM、DLP、manifest、测试证据和 `SHA256SUMS`。
- App 包不得携带数据库、索引、Neo4j、运维组件、生产配置或 secrets；服务端包不得被 App 当作前端运行包。
