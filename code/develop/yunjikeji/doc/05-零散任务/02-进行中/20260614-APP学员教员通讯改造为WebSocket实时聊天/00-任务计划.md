## 2. 任务目标

1. 将后端现有 `com.huiyitech.message.controller.app` 消息 APP 接口，按仓内其他 APP 模块方式迁移到 `com.huiyitech.app.message`，并保持 controller 结构与原有 URL 不变。
2. 为 APP 学员端与教员端聊天补齐 WebSocket 实时通讯能力：新消息实时送达、实时追加、消息继续入库、刷新或重新进入后继续按现有历史查询逻辑回放。
3. 补齐 APP 聊天图片、视频发送能力：媒体文件上传百度 BOS，消息表写入 BOS 地址，并同时兼容历史查询与实时聊天链路。

## 3. 任务范围

- 包含：
  - 后端 APP 消息 controller / vo / service 迁移到 `com.huiyitech.app.message`
  - 后端复用现有 `/infra/ws` 补齐学员端与教员端实时文本/图片/视频聊天收发、入库与定向广播
  - 后端在管理平台 `com.huiyitech.utils` 新增百度 BOS 配置与工具，桶名使用 `yunjikeji`
  - 前端聊天页接入 WebSocket，保留现有历史查询逻辑并对接实时消息
  - 前端聊天页补齐图片、视频选择上传、展示与预览/播放
  - H5 本地联调所需的 WebSocket 代理配置
- 不包含：
  - 不改动 `uni_modules/**`
  - 不改变现有聊天历史查询接口的业务语义

## 4. 统一原则

- 历史查询逻辑保持为页面进入后的正式回放入口，实时消息只负责当前会话内追加，不替代历史查询。
- APP 侧消息接口迁移只调整 package / import / 组织方式，不改变既有 `/app-api/yj/customer-service/**` 与 `/app-api/yj/company-students/**` 对外路径。
- 实时消息必须与真实入库联动；禁止只做前端假追加、不落数据库的伪实时方案。
- 图片、视频消息走 HTTP 上传链路，不直接通过 WebSocket 透传原始文件；正式链路为“上传文件到 BOS -> 落库 BOS 地址 -> WebSocket 广播新消息”。
- `yj_message_info.message_type` 使用前端兼容值 `image`、`video`；`content` 存储 BOS 地址，历史查询与实时消息复用同一展示逻辑。
- 若 WebSocket 暂时不可用，文本发送允许回退现有 HTTP 发送接口，避免聊天完全中断。
