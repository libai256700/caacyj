## 2026-06-14 补充定位

使用 Chrome DevTools MCP 复现 `13111111112 / 123456` 企业登录：

- `POST /app-api/yj/company-auth/login-or-register` 返回 `tenantId:null`。
- `GET /app-api/yj/company-auth/post-codes?mobile=13111111112` 返回 `userMatched:true`、`postCodes:["WT"]`、`hasWtPost:true`，但旧运行进程响应中没有 `tenantId`。
- `POST /app-api/yj/company-auth/refresh-token` 返回 `tenantId:null`。
- 前端本地 session 最终为 `tenantId:null`、`hasWtPost:true`。
- 消息页 `loadEnterpriseStudents()` 因 `tenantId` 为空直接显示“未获取到企业租户信息，点击重试”，没有发出新的 `GET /app-api/yj/company-students`。

结论：

- 不是因为没有调用 `/app-api/yj/company-auth/me`。
- 根因是 WT 快捷进入消息页时没有可用租户编号写入 `appState.userSession.tenantId`。
- 已补充后端 `post-codes` 返回匹配后台用户的 `tenantId`，并让前端 WT 分支把该值合并进刷新后的 session。
- 本机 48080 后端由 IDEA Java 进程运行，编译不会自动替换运行中类；需重启后端或部署后再做端到端复验。
