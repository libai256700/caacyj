# 企业登录 WT 岗位分流实施记录

## 实施结论

- 后端新增 `GET /app-api/yj/company-auth/post-codes`，企业登录后携带企业 token 调用。
- 接口按 `system_users.mobile` 匹配后台用户，汇总 `post_ids`，关联 `system_post.id` 后返回岗位 `code` 列表和 `hasWtPost`。
- 前端企业登录后先写入登录 session，再调用岗位接口；命中 `WT` 时刷新 token 并进入 `/pages/service/customer-service`。
- 未命中 `WT`、未查到用户、未查到岗位、接口普通异常时，回退原有 `auditStatus` 分流；若岗位接口触发鉴权失效并清空 session，则中断登录并走现有重新登录处理。

## 实现备注

- `system_users.post_ids` 当前 DO 映射为 `Set<Long>`，底层表字段为 varchar JSON；实现复用 `AdminUserDO.postIds` 的 `JacksonTypeHandler` 映射结果。
- 为避免手机号在多租户或历史数据中重复导致 `selectOne` 异常，接口按手机号取列表并合并所有岗位。
- `WT` 判断使用大小写不敏感的包含判断，满足“code 包含 WT”要求。
