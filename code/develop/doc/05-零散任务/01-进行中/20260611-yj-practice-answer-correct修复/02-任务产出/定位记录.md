# 定位记录

## 现象

- 页面：题目管理 -> 配置可选项。
- 样本：题目 `#2768`。
- 页面列：“正确答案”显示为“停用”。
- 期望：显示“是”或“否”。

## 调用链核对

### 后台管理链路

- 前端配置入口：`yunjikeji-admin-ui/src/views/yj/resource/config.ts`
- 页面渲染入口：`yunjikeji-admin-ui/src/views/yj/resource/index.vue`
- API 入口：`/practice/practice-exercises-answer/page`
- 后端控制器：`PracticeExercisesAnswerController`
- 后端服务：`PracticeExercisesAnswerServiceImpl`
- 数据对象：`PracticeExercisesAnswerDO`
- 目标表：`yj_practice_exercises_answer`

后台管理链路中，`PracticeExercisesAnswerDO.correct` 通过 `@TableField("is_correct")` 映射到数据库字段 `is_correct`；`AbstractPracticeResourceService` 返回给前端时也会把实体属性 `correct` 转成 `is_correct`。这条链路没有发现把正确答案字段映射成状态字段的问题。

### 学员端练习链路

- 代码入口：`yunjikeji-server/src/main/java/com/yunjikeji/server/practice/PracticeService.java`
- 查询入口：`yk_question`、`yk_question_option`
- 判题依据：`yk_question.correct_answer`

`yunjikeji-server` 当前练习判题并不直接读取 `yj_practice_exercises_answer.is_correct`；提交答案时会把用户选择和 `yk_question.correct_answer` 归一化后比较。因此截图中的后台弹窗显示问题，不是 `yunjikeji-server` 学员端接口直接把字段返回错。

## 根因结论

### 显示文案根因

`yunjikeji-admin-ui/src/views/yj/resource/index.vue` 的通用 `formatCell` 对所有 `switch` 字段统一返回：

- `true` -> `启用`
- `false` -> `停用`

“正确答案”字段 `is_correct` 也是 `switch` 类型，所以 `false` 被显示成“停用”。这是前端通用布尔字段显示文案过于单一导致的程序问题。

### 数据标记结论

题目 `#2768` 的选项 `is_correct` 均为 `0`。它属于 `category_id = 13` 的“入行专属评估”调查问卷；导入记录明确写明“单选/多选题写入选项，所有 `is_correct` 均为 `b'0'`，避免把调查问卷选项误标为标准答案”。因此 `#2768` 没有正确答案标记，是迁移策略结果，不是程序运行时丢字段。

## 已实施修复

- 为 `YjField` 增加 `switchLabels` 配置。
- 将题目选项、答题记录、自测答案等 `is_correct` 字段显示配置为：
  - `true` -> `是`
  - `false` -> `否`
- 普通状态字段仍保持默认：
  - `true` -> `启用`
  - `false` -> `停用`

## 未做数据强改的原因

- “入行专属评估”是调查问卷，不是考试标准题，现有导入记录没有标准答案来源。
- 对 `#2768` 或同类问卷题随意设置正确答案，会把问卷选项伪造成标准答案。
- 另有普通题 `id = 28` 主表记录正确答案为 `C`，但当前选项只有 `A/B`，无法仅通过 `is_correct` 回填解决，必须补齐真实 C 选项来源后再修。
