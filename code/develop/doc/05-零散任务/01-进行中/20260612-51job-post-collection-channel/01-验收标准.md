# 前程无忧岗位采集渠道接入验收标准

## 业务验收

### A1 业务-交互线：采集来源下拉出现前程无忧
- 业务起点：管理员打开管理平台“采集配置”，新增或编辑采集任务。
- 触发动作：展开“采集来源”下拉框。
- 关键交互：下拉选项包含“前程无忧”，并能保存为采集任务渠道。
- 业务终点：采集任务后续执行时能按该渠道路由到前程无忧实现。
- 结果承接：岗位采集实例和岗位明细中的来源可显示为字典名称。
- 核对方式：字典脚本、前端字典显示、后端渠道 value 一致性核对。
- 当前状态：已通过。前程无忧字典项已新增为 `51job`，并与后端渠道 code 保持一致。

### A2 业务-交互线：前程无忧渠道按真实规则采集岗位，BOSS 直聘不再实现
- 业务起点：存在启用状态、采集来源为前程无忧或 BOSS 直聘的采集配置。
- 触发动作：执行立即采集或定时采集。
- 关键交互：前程无忧按参考技能包逻辑请求和解析岗位结果；BOSS 直聘实现置空，不继续执行旧采集逻辑。
- 业务终点：前程无忧结果可进入岗位实例链路；BOSS 直聘返回清晰不实现边界，不生成伪造岗位结果。
- 结果承接：后续排查可通过任务实例、岗位实例、日志和异常信息区分渠道行为。
- 核对方式：代码路径、字段映射、局部运行或测试记录核对。
- 当前状态：已通过（有风险说明）。前程无忧渠道已接入真实网页采集解析链路；BOSS 直聘已置空并返回空结果。未执行真实线上联调，外部站点反爬或页面结构变化仍可能导致空结果。

## 技术验收

### T1 技术-接口线：渠道 value 与服务路由一致
- 正式入口：采集来源字典、采集任务保存接口、岗位采集服务路由。
- 支撑的业务结果：“前程无忧”保存后能被后端识别并路由到对应实现。
- 技术边界：不得只新增前端下拉文案而缺少后端服务实现；不得使用与字典不一致的渠道 code。
- 通过条件：字典脚本 value、后端 platform source、服务实现声明一致。
- 证据承接方式：事实清单、实施记录、代码 diff。
- 当前状态：已通过。

### T2 技术-数据线：字典新增脚本幂等且可校验
- 正式入口：`yunjikeji-admin-server/sql/mysql/` 下新增或更新的字典脚本。
- 支撑的业务结果：测试/部署环境执行脚本后，采集来源字典包含“前程无忧”。
- 技术边界：本任务不直接操作生产数据库；脚本需可重复执行。
- 通过条件：脚本包含 `system_dict_type` 前置或依赖说明、`system_dict_data` 幂等写入和执行后校验 SQL。
- 证据承接方式：SQL 脚本、验证记录。
- 当前状态：已通过。

### T3 技术-代码线：前程无忧实现符合现有渠道结构和参考技能包
- 正式入口：后端岗位采集服务实现类、服务工厂或 Spring 注入集合。
- 支撑的业务结果：前程无忧采集返回岗位名称、企业名称、薪资范围、工作区域、发布时间、详情地址、来源 code 等字段。
- 技术边界：不得用假数据冒充真实采集；外部访问失败时需清晰返回失败边界。
- 通过条件：实现类接入现有结构，字段映射与参考技能包一致或有明确说明，异常处理不破坏任务实例链路。
- 证据承接方式：事实清单、实施记录、代码 diff、测试或编译记录。
- 当前状态：已通过（有风险说明）。代码已按真实页面采集链路实现，不造假数据；未执行真实 51job 线上联调。

### T4 技术-代码线：BOSS 直聘实现已置空
- 正式入口：`BossZPPlatformPostCollectServiceImpl`。
- 支撑的业务结果：选择 BOSS 直聘时不再运行旧采集解析逻辑。
- 技术边界：不得保留旧解析实现继续生效；不得返回伪造成功数据。
- 通过条件：该类实现明确为空/不予实现，并以空结果或清晰异常边界表达当前不支持。
- 证据承接方式：代码 diff、验证记录。
- 当前状态：已通过。
