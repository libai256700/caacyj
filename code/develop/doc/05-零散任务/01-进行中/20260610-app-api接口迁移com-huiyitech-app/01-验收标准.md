# APP 接口迁移到 com.huiyitech.app 验收标准

## 业务验收

### A1 业务-交互线：前端 APP 接口契约不变

- 业务起点：前端 APP 继续请求原有 `/app-api/**` 接口。
- 触发动作：调用迁移前已有 APP 端接口。
- 关键交互：请求路径、HTTP 方法、参数、响应结构和业务语义保持不变。
- 业务终点：APP 侧可按原契约获得相同业务结果。
- 结果承接：以代码映射核对、编译/测试结果和必要接口入口检查作为证据。
- 状态：未执行。

## 技术验收

### B1 技术-接口线：APP 接口代码归位

- 正式入口：`yunjikeji-admin-server` 源码中的 `/app-api/**` controller 及其直接配套代码。
- 支撑结果：APP 端接口相关实现位于 `com.huiyitech.app` 包下，风格参考 `FrontTenantController`、`FrontTenantService`、`FrontCompanyAuditController`。
- 技术边界：不要求改动业务逻辑，不迁移 `/admin-api/**` 后台接口。
- 通过条件：源码搜索显示 APP 接口入口已归入目标包或存在明确保留原因。
- 状态：未执行。

### B2 技术-代码线：业务逻辑无变化

- 正式入口：迁移涉及的 controller、service、vo/dto、mapper 调用与依赖注入。
- 支撑结果：仅做包结构、类位置、import 和引用适配。
- 技术边界：不新增业务分支、不改数据库语义、不改权限语义。
- 通过条件：差异检查未出现非必要业务逻辑改写。
- 状态：未执行。

### B3 技术-代码线：admin-api 保持当前结构

- 正式入口：源码中的 `/admin-api/**` controller 及其服务结构。
- 支撑结果：后台管理接口不随本次 APP 迁移移动包结构。
- 技术边界：允许因 import 或共享依赖变化产生必要引用调整。
- 通过条件：`/admin-api/**` controller 仍保持原有包结构。
- 状态：未执行。

### B4 技术-接口线：项目构建或测试通过

- 正式入口：`yunjikeji-admin-server` 的 Maven/Gradle 构建或仓库现有测试命令。
- 支撑结果：迁移后的包名、Spring 扫描、依赖注入和编译引用有效。
- 技术边界：若测试依赖外部环境不可执行，至少完成可执行的本地编译检查并记录阻塞原因。
- 通过条件：本地构建/测试命令通过，或不可执行项有明确说明。
- 状态：未执行。
