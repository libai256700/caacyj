# 岗位采集实例链路改造任务计划

## 任务目标

依据 `yunjikeji-admin-server/doc/数据库表结构说明.md`，将测试数据库岗位采集相关表结构调整到最新口径，并改造岗位采集链路：采集任务启动时创建任务实例，采集结果先写入任务实例，采集完成后按岗位名称、企业名称、薪资范围、工作区域四字段联合去重合入 `yj_post`，合入成功后任务实例状态改为 `3`。同时核对并补齐 BOSS 直聘、猎聘、智联招聘、国聘四个渠道实现，严格参考 `E:\内容\岗位skill\岗位采集技能包`。

## 任务范围

1. 读取数据库表结构说明，确认 `yj_post`、`yj_post_instance`、`yj_post_collection_task_instance` 的字段、索引、租户边界和状态口径。
2. 生成并执行测试库 DDL/DML 脚本，更新 `yj_post`，创建 `yj_post_instance`、`yj_post_collection_task_instance`。
3. 修改后端采集链路：定时采集和立即采集均创建任务实例，采集明细先写实例表，再合入正式岗位表。
4. 实现正式岗位表按采集岗位名称、企业名称、薪资范围、工作区域联合去重；重复数据不写入 `yj_post`。
5. 核对 BOSS 直聘采集实现与岗位采集技能包一致性。
6. 补齐猎聘、智联招聘、国聘渠道采集服务实现并接入工厂。
7. 补充必要测试、执行验证，记录数据库执行和代码验证结果。
8. 检查通过后提交并推送远程；最终等待用户审核。

## 统一原则

1. 不修改 `uni_modules/**`。
2. 不直接操作生产数据库；本次只允许操作测试数据库，且数据库写操作必须脚本化并保留执行记录。
3. 测试库 DDL/DML 执行前先确认连接入口和当前库名；如正式记录缺失或连接失败，立即停止并请求用户干预。
4. 外部采集规则以 `E:\内容\岗位skill\岗位采集技能包` 为符合性依据，不用假数据冒充真实采集逻辑。
5. 沿用当前工作分支，不新建独立分支。
