# 管理平台知识库管理测试入口验收标准

## 业务验收

### A1 业务-交互线：知识库管理列表出现两条启用数据

- 业务起点：管理平台用户进入“知识库管理”页面。
- 触发动作：页面加载知识库列表。
- 关键交互：列表中可看到“云技科技原知识库”和“考试知识库”，状态均为启用。
- 业务终点：两条数据作为正式列表数据展示，而不是前端硬编码假行。
- 结果承接：后续可按页面既有查询、分页或刷新逻辑持续看到对应数据。
- 核对方式：页面展示、接口返回、数据库记录三者核对。
- 当前状态：未通过，待实施验证。

### A2 业务-交互线：两条知识库记录均可执行测试并展示结果

- 业务起点：列表中存在启用状态的目标知识库记录。
- 触发动作：点击对应行操作列“测试”按钮。
- 关键交互：弹出输入框，输入问题后点击“测试”。
- 业务终点：云技科技原知识库返回本地 ask 接口结果；考试知识库返回 fly-llm APP 错题 AI 解析知识库接口结果。
- 结果承接：返回内容以弹框展示；接口失败时展示明确错误信息。
- 核对方式：浏览器交互、请求记录、弹框内容或错误提示核对。
- 当前状态：未通过，待实施验证。

## 技术验收

### T1 技术-数据线：知识库管理页面对应表已确认且数据写入可复核

- 正式入口：管理平台知识库管理页面列表接口和对应数据库表。
- 支撑的业务结果：目标两条知识库数据来自真实表记录。
- 技术边界：只允许操作开发/测试环境；不得直接写生产库。
- 通过条件：事实清单记录表名、关键字段、状态取值、写入方式和执行结果；数据库中存在两条启用记录。
- 证据承接方式：`02-任务产出/事实清单.md`、SQL/接口执行记录、查询结果。
- 当前状态：未通过。

### T2 技术-接口线：两个测试按钮请求真实目标接口

- 正式入口：云技科技原知识库请求 `http://127.0.0.1:5001/api/ask?q=XXXX`；考试知识库请求 fly-llm APP 错题 AI 解析知识库接口。
- 支撑的业务结果：用户输入的问题被发送到对应知识库问答服务。
- 技术边界：不得用静态假响应冒充接口结果；接口不可用时按失败提示处理。
- 通过条件：代码中存在按知识库记录区分目标接口的实现，参数正确编码，返回结果进入弹框展示。
- 证据承接方式：代码 diff、请求封装说明、局部验证记录。
- 当前状态：未通过。

### T3 技术-代码线：页面实现复用现有组件和请求封装

- 正式入口：管理平台知识库管理正式页面源码。
- 支撑的业务结果：操作列测试能力与页面现有风格、权限和请求体系一致。
- 技术边界：不新增第二套同义页面；不残留临时测试页、调试文案或硬编码假列表。
- 通过条件：弹框、输入框、按钮、消息提示优先复用项目现有 UI 组件；代码通过可用静态检查或构建。
- 证据承接方式：实施记录、验证记录。
- 当前状态：未通过。

### T4 技术-数据线：写入脚本或接口具备幂等性

- 正式入口：本任务的数据补齐 SQL、脚本或后端接口。
- 支撑的业务结果：重复执行不会产生重复知识库记录。
- 技术边界：不得通过手工不可追溯操作完成数据写入。
- 通过条件：写入逻辑以名称或业务唯一字段判断存在后再插入/更新，执行结果已记录。
- 证据承接方式：SQL/脚本、执行记录、查询结果。
- 当前状态：未通过。
