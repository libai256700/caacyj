## 一、约定与通用字段

绝大多数业务表都遵循以下设计约定：

| 字段 | 类型 | 含义 | 说明 |
|---|---|---|---|
| `id` | `bigint AUTO_INCREMENT` | 主键编号 | 几乎所有业务表的主键 |
| `creator` | `varchar(64)` | 创建者 | 通常存放用户 ID 字符串 |
| `create_time` | `datetime` DEFAULT CURRENT_TIMESTAMP | 创建时间 | |
| `updater` | `varchar(64)` | 更新者 | |
| `update_time` | `datetime` ON UPDATE CURRENT_TIMESTAMP | 更新时间 | |
| `deleted` | `bit(1)` DEFAULT b'0' | 是否删除 | 逻辑删除标记，0=未删除，1=已删除 |
| `tenant_id` | `bigint` DEFAULT 0 | 租户编号 | 多租户隔离字段，绝大多数业务表都有 |

> 下文各表字段说明中，凡未特别强调的通用字段不再重复列出，仅在出现差异时单独说明。

## 十四、Quartz 调度模块（QRTZ_*）

Quartz 标准持久化表，由 Quartz 框架自身使用，不建议手工修改。

| 表名 | 用途 |
|---|---|
| `QRTZ_JOB_DETAILS` | 存储 JobDetail 信息（任务名、类、是否持久化等） |
| `QRTZ_TRIGGERS` | 存储 Trigger 通用信息 |
| `QRTZ_SIMPLE_TRIGGERS` | 简单触发器（按固定间隔执行） |
| `QRTZ_CRON_TRIGGERS` | Cron 触发器 |
| `QRTZ_SIMPROP_TRIGGERS` | 自定义属性触发器（DailyTimeInterval / CalendarInterval 等） |
| `QRTZ_BLOB_TRIGGERS` | 自定义 Trigger 序列化存储 |
| `QRTZ_CALENDARS` | 日历对象（用于排除特定时间） |
| `QRTZ_FIRED_TRIGGERS` | 正在执行的 Trigger 状态 |
| `QRTZ_PAUSED_TRIGGER_GRPS` | 暂停的 Trigger 组 |
| `QRTZ_SCHEDULER_STATE` | 集群环境下各调度实例状态 |
| `QRTZ_LOCKS` | 集群行锁，用于分布式同步 |

主键多为 `(sched_name, trigger_name, trigger_group)` 或 `(sched_name, job_name, job_group)`，所有表通过 `sched_name` 实现多调度器共用一套表。

## 附：阅读建议

1. 业务开发优先关注 **system_users / role / menu / dept / dict** 等核心 RBAC 与字典表。
2. 多租户场景下所有业务表都会自动注入 `tenant_id`，禁止手动跨租户跨表查询。
3. 删除操作均为逻辑删除（`deleted = 1`），物理删除请通过 DBA 处理。
4. 日志类表（`system_login_log`、`system_operate_log`、`infra_api_access_log`、`infra_api_error_log`、`system_mail_log`、`system_sms_log`、`infra_job_log`）数据量增长较快，建议按时间归档/分表。
5. Quartz 表无需在业务代码中直接操作，统一通过 `infra_job` + Spring Quartz 调度即可。

> 字段完整定义（含字符集、索引、AUTO_INCREMENT 起始值等）请以源 SQL 文件为准：
> - `sql/mysql/ruoyi-vue-pro.sql`
> - `sql/mysql/quartz.sql`
