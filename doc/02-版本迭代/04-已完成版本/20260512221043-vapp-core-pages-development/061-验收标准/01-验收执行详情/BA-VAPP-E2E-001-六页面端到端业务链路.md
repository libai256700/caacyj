# BA-VAPP-E2E-001 六页面端到端业务链路

## 验收类型

`端到端业务验收`

## 业务场景

用户从正式测试环境入口进入后，完成登录并依次访问 `首页 / 练习开始页 / 练习页 / AI深度解答页 / 我的页`，确认六个正式页面的主链路成立。

## 验收标准说明

六个正式页面必须按当前版本设计与业务流程可进入、可操作、可返回或切换；页面展示、主按钮、关键状态、异常提示和导航关系不得依赖假数据冒充真实联调效果。页面视觉与布局类验收证据固定只接受移动端设备模式下的运行态截图；桌面布局截图、桌面截图裁切图或缩放图一律不作为正式通过依据。

## 核心对象

- `登录页`
- `首页`
- `练习开始页`
- `练习页`
- `AI深度解答页`
- `我的页`
- 测试环境前端正式访问入口
- 页面到后端接口调用链路

## 前置条件

1. `TASK-018-04`、`TASK-018-05` 已完成测试环境后端和前端预备现场。
2. 前端访问 URL、后端 API 路由和鉴权口径已写入正式记录。
3. 联调用测试账号、验证码或 Token 获取方式已确认。
4. 六个页面对应后端接口已具备测试环境可访问入口。
5. 页面验收所用浏览器通道已能进入移动端设备模式，并可保留设备参数与运行态截图证据。

## 触发动作

1. 以移动端设备模式打开测试环境前端正式入口。
2. 完成登录。
3. 按业务顺序进入首页、练习开始页、练习页、AI 深度解答页和我的页。
4. 在每个页面触发至少一个主业务动作或主状态刷新。
5. 记录移动端设备参数、页面结果、接口返回和异常提示。

## 期望结果

1. 六个页面均可从正式入口进入且无白屏、无阻断性报错。
2. 页面主链路、Tab 切换和页面跳转符合当前版本设计。
3. 关键页面状态来自真实接口或正式结果载体，不以静态假数据替代。
4. 失败态、空态和异常提示可识别，不出现用户无法继续操作的死路。
5. 页面视觉、高保真与布局结论均基于移动端设备模式运行态截图得出，不存在用桌面截图裁切替代移动端证据的情况。
