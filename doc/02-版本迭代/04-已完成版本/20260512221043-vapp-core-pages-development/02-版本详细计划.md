## 3. 统一原则

- 默认责任分工：设计、开发、脚本、部署、发布、结果回写类任务由智能体执行；人工测试、人工复测、人工审核、用户复验、人工验证类任务由人类执行；主线程负责调度、回写和状态流转。
- 任务执行者口径：任务总表必须显式区分 `智能体` 与 `人类`；同一任务不得同时承接开发和测试。
- 正式页面范围：本版正式页面固定为 `登录页 / 首页 / 练习开始页 / 练习页 / AI深度解答页 / 我的页`；`首页/废除` 下旧稿不纳入开发、不纳入验收。
- 正式设计输入：页面设计统一以 `D:\ProjPort\Work\feixingxueyuan\doc\02-版本迭代\03-进行中版本\20260511100000-vinit-project-bootstrap\031-页面设计\003-具体页面` 为正式来源。
- 背景资源使用口径：页面背景优先从以下正式输入中择近使用，允许后续微调，但当前计划必须视为正式输入：`001-登录背景\03-生成图片-001.png`、`001-登录背景\03-生成图片-003.png`、`002-重点氛围背景\03-生成图片-001.png`。
- 任务拆分口径：当前版本按“单页单 Story”推进；`登录页 / 首页 / 练习开始页 / 练习页 / AI深度解答页 / 我的页` 各自独立 Story；每个 Story 至少拆成 10 个正式子任务，且每个子任务最多只绑定 1 个主技能。
- 页面测试顺序口径：当前版本严格执行“开发 + 人工测试 + 开发 + 人工测试”穿插推进；每个页面 Story 完成当前一轮开发后，必须立即进入人工测试并回写结果，未完成该轮人工测试前，不得继续堆积后续页面开发或集中到最后统一测试。人工测试至少覆盖高保真设计对比、基本交互正常、前后端拉通。
- 页面人工审核口径：每个页面 Story 的开发任务完成后先回写为 `已完成`，再由对应“人工测试与审核”任务承接人类审核；用户未明确审核通过前，不得启动依赖该审核结果的后续页面开发；如用户指出高保真、交互或资源偏差，对应页面开发 Story 立即回退为 `进行中` 并补充重做子任务。
- 实施前先阅读任务详情：任务总表只做导航；真正实施前，必须先从主计划跳转并通读对应 `020-任务详情/` 文件。
- 计划启动门禁：只要“版本代码现场”未写清、“正式验收入口”未收口，或当前任务还没有对应任务详情文件，任何任务都不得进入 `进行中`。
- 数据库执行口径：数据库相关工作必须按正式规范与脚本方式推进，至少覆盖库表设计、建表脚本、测试库验证与结果回写，不得只停留在连接配置层。
- 持续测试口径：开发过程中必须按“开发一段、人工测试一段、通过后再继续开发下一段”的节奏推进；所有测试均以人工执行和人工回写为准，不再采用“先累计大量开发、最后集中测试”的推进方式。
- 正式验收口径：正式验收由人工执行并回写；当前版本只保留“通知用户并等待明确发布允许”这一发布门禁。
- 版本通过判定：只有当测试环境全部正式验收标准通过、发布允许已明确、生产发布完成、发布后同步完成时，才允许判定版本通过。

## 4. 版本目标

1. 以前端正式页面设计输入为依据，把 `登录页 / 首页 / 练习开始页 / 练习页 / AI深度解答页 / 我的页` 分别作为独立 Story 推进。
2. 每个页面 Story 至少拆成 10 个正式子任务，覆盖设计、验收、后端、数据库、前端、人工测试与结果回写，并显式包含“开发 -> 人工测试 -> 再开发 -> 再人工测试”的穿插收口链路，不再保留粗粒度混合任务。
3. 完成公共骨架、三 Tab 公共状态与背景资源落位，保证六个正式页面的统一体验基线。
4. 完成后端项目基础能力、数据库规范化建表、测试库验证，支撑登录、首页聚合、练习链路、AI 深度解答、我的页聚合等业务能力。
5. 在开发过程中持续推进前后端联调、人工测试、测试环境部署与正式验收闭环；任何页面或链路只有在上一轮人工测试完成并回写后，才允许进入下一轮开发或下一阶段任务。
