# DEV-063 模式2-5批量生成提速

## 实施标准

- 模式 1 逐题练习保持不变；模式 2-5 的题目最终顺序继续以 Java 已生成的 `orderedExercises` 为准，不再在 `yj_practice_exercises_batch` 上做二次重排 `UPDATE`。
- `yj_practice_exercises_batch` 采用集合式 `INSERT ... SELECT` 一次性写入 `catalog_batch_id`、`custom_account_id`、`exercises_id` 和最终 `sort_no`；题目 batch 生成过程不得拆成逐题插入后再修正排序。
- `yj_practice_exercises_answer_batch` 通过 `exercises_batch_id` 关联题批次，一次性写入 `answer_id`、`answer_content`、`is_correct`、最终 `sort_no` 与 `answer_code`；`answer_code` 必须随最终 `sort_no` 生成 A/B/C...，不恢复 `catalog_batch_id`。
- 模式 2-5 的原有选题规则保持不变，模式 4 九分类固定配额保持不变；仅压缩 batch 生成链路，不改变题库筛选结果。
- 批次生成、答案插入与映射更新必须放在同一事务内；任一环节失败时整体回滚，避免半成品批次和错位答案。
- SQL 方案必须兼容 MySQL 5.7；若需要题内随机排序，应使用可兼容的稳定排序方案，不依赖 8.0 专属窗口函数。
