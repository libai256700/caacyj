# DEV-028 企业端教员选学员会话与学员端客服兼容修复

## 实施标准

- 真实业务路径固定为“教员登录 -> 底部客服 -> 分页学员列表 -> 点击任一页具体学员 -> 与该学员的会话页”。企业客服列表通过分页全局展示所有符合既有审核通过条件的学员并 LEFT JOIN 会话，包括尚未加入组织且账号 `tenantId=null` 的学员；全局可见以遍历分页结果实现，不要求一次自动加载全部。列表与进入会话页不依赖当前教员或学员账号 tenant 是否存在，也不按 `tenant_id` 缩小可见范围。
- 分页固定 `pageSize=50`；以 101 名可区分审核通过学员形成 3 页，首次请求 `pageNo=1`，上一页 / 下一页依次请求 `pageNo=1/2/3`。首页禁用上一页，末页禁用下一页，中间页两者可用；每次翻页只展示该页响应，不把前页、后页或重复学员残留 / 追加到当前页，返回上一页时恢复对应页数据。此前任何 `pageSize=100` 口径作废。
- 已有会话时，必须进入并复用所选学员同一真实 conversation，完整加载历史并继续发送；不得创建重复会话，不得回退或串用空 / default / synthetic conversationId。
- 无会话时，允许进入明确的空会话态；空态、历史 GET 和首次发送不得以教员或学员 tenant 非空为前置条件。历史 GET 不得创建新 session；对 `conversationId + studentId` 已校验的既有 session，允许沿用既有 `bindSessionReceiver` 绑定当前教员接收方，以保持 WebSocket 实时收件，该绑定不属于隐式 start/create。教员首次发送前必须显式 start/create，取得后端返回的真实 `conversationId` 后再发送；后续历史查询、消息发送和 WS 均使用该 ID。
- 列表、空态、已有会话关联、历史 GET、发送和 WS 均不得以 `tenant_id` 作为可见或权限过滤条件。tenant 仅作为存储事实：已有 session 与消息沿用各自实际非空持久 `tenant_id`；尚未加入组织的学员首次 start/create 产生的新 session 与消息必须复用学员端既有规范化规则，将账号 `tenantId=null` 持久化为 `tenant_id=1`。不得把账号空值传播到 session/message，不得新增或臆造其他默认 tenant，也不得反向限制教员可见范围。
- 分页学员列表点击上下文、会话页解析、历史 GET、显式 start/create、发送和 WS 契约必须一致。点击任一页任一行时必须传递该行真实 `studentId` 及已有真实 `conversationId`；无会话行不得拼装 ID，显式 start/create 后才使用后端返回的真实 `conversationId`。所有已有与新建会话均以 `studentId + conversationId` 校验归属并防止跨页或串学员，不得在前端拼装 synthetic conversationId。只写可验证契约，不在取证前指定其他未知参数名、响应字段或存储实现。
- 学员端从 `profile.vue` 原“联系客服”入口进入会话页时，即使尚未加入组织且 `tenantId=null`，也必须继续保持既有会话创建 / 复用、历史加载、发送和退出重进能力；企业端修复不得改变学员端既有 `/app-api/yj/customer-service/**` 会话语义或既有未入组织创建存储规则。
- H5 环境缺少 `uni.onKeyboardHeightChange` / `uni.offKeyboardHeightChange` 时必须受能力检查保护；具备能力的平台继续保持原监听与清理行为。分页列表的固定页大小、页码请求、按钮禁用、数据替换和任意页点击上下文，以及历史加载、发送和非 H5 逻辑均不得回退。
- 本次禁止数据库变更，不新增唯一索引或约束。当前无数据库唯一约束下，并发首次联系同一无会话学员仍可能产生重复 session；该项登记为残余风险，不得声称已实现强并发唯一。
- 先在 `061-验收标准/03-测试验证/DEV-028/` 分别建立企业端教员与学员端失败原因正确的红灯，再做最小实现转绿；接口级、数据级和 `chrome-devtools-mcp` 浏览器交互级集成验收在测试环境执行。
- 实施代理不得承担独立验收；独立验收代理不得顺手修改实现。禁止修改数据库和 `uni_modules/**`。
