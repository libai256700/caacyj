# DEV-028 测试范围

## 接口级

- 企业端列表按正式分页接口返回所有符合既有审核通过条件的真实学员记录，不按当前教员 tenant 过滤；正式分页固定 `pageSize=50`，前端必须提供可操作的上一页 / 下一页并传递真实 `pageNo`，不能只固定读取第 1 页。尚无会话的学员 `conversationId` 必须为空，同一学员的多条真实 session 均可精确选择。
- 无会话学员首次联系必须调用显式 start 接口取得真实 `conversationId`，历史 GET 不得隐式创建；对 `studentId + conversationId` 已精确校验的既有 session，允许保留 `bindSessionReceiver` 接收方绑定以维持 WebSocket 实时收件，该更新不得被误判为 start/create。
- 企业端历史、HTTP 文本/媒体发送和 WebSocket 发送统一携带 `conversationId + studentId`。
- 后端按 `session.id = conversationId AND session.session_from = studentId` 校验，查询与写入使用 session 自身 `tenant_id`，不得 `getOrCreate`。
- 发送后按新增 `messageId` 精确返回消息，不从历史第一页猜测新增消息。
- 学员端继续使用 `/app-api/yj/customer-service/session` 与 `/app-api/yj/customer-service/messages`。

## 数据级

- 企业端所读、所写消息的 `session_id` 始终等于所选 `conversationId`。
- `conversationId` 与 `studentId` 错配时拒绝，不读取、不写入、不创建会话。
- 当前企业 tenant 与会话持久化 tenant 不同时，仍可读取和发送所选会话，新增消息与会话快照沿用会话持久化 tenant。
- 首次 start 从已锁定并核验的目标学员记录读取其自身 tenant；事务内锁定目标记录后复查已有 session，避免同一入口并发重复创建。当前教员 tenant 不参与可见性、授权或 session 选择。
- 超过 200 条的企业端历史按页全部加载；同一学员存在多条 session 时不合并。

## 交互级

- H5 缺少键盘高度 API 时页面正常进入；具备 API 的平台仍注册并清理监听。
- 企业客服学员列表必须可逐页浏览：以 101 名可区分审核通过学员验证 `pageSize=50` 时三页依次为 50、50、1 条；第 1 页禁用上一页，第 3 页禁用下一页，翻页请求携带对应 `pageNo` 和 `pageSize=50`，页码正确且翻页后不混入前一页数据；页面重新显示时明确回到第 1 页，翻页失败保留最近一次成功页；每页点击已有会话或无会话学员时，继续传递该行真实 `studentId` 与可空的真实 `conversationId`。
- 企业端从客服列表进入具体既有 conversation，完整历史、发送和退出无错。
- 学员端原入口创建或复用会话、历史、发送和退出重进不回退。
- 交互独立验收由不同代理在测试环境使用 `chrome-devtools-mcp` 执行，本实施代理不执行、不判定最终通过。

## 已知残余风险

- `yj_session_message` 未见 `(session_from)` 唯一约束，本任务禁止数据库变更。显式 start 通过事务内锁定目标学员关系行并复查来尽力复用；不宣称所有旧入口或跨实现路径具备数据库级强并发唯一。
