# TC-UI-CAREER-ASSESS-001 首页点击后双选择层

## 1. 测试层级

`交互级`

## 2. 对应验收项

- 验收项 ID：`AC-CAREER-ASSESS-001/002/301`
- 正式验收入口：`../../01-验收执行详情/AC-CAREER-ASSESS-001.md`

## 3. 前置条件

- 环境前置：DEV-070 只执行源码结构红灯；真实浏览器交互留待功能实现后的测试环境 Playwright 验收。
- 账号前置：无。
- 数据前置：`test-data.json`。

## 4. 测试数据

首页原单个“开始测评”和“评测结果”入口；点击后分别出现两项选择层。

## 5. 执行动作

| 步骤 | 动作 | 预期结果 |
| --- | --- | --- |
| 1 | 结构化解析 `home.vue` 模板和 TypeScript AST | 首页仍各有一个原入口，原入口先打开条件选择层 |
| 2 | 检查两层选项及唯一事件绑定 | 自评选项只关闭本层并调用原函数；职业规划选项只关闭本层并调用唯一分类14平行动作 |
| 3 | 遍历根dialog、遮罩节点自身及全部后代事件 | 取消、遮罩、关闭及其他非选项事件零外部调用，只允许把所属dialog状态设为false；无表达式事件只允许惯性传播修饰符 |
| 4 | 执行内置mutation | 根/遮罩/关闭增加请求、自评增加导航、职业规划增加第二动作、选项增加第二事件均被拒绝 |

## 6. 期望结果

- 当前实现因缺少两层选择而准确红灯。
- 功能实现后必须使用 Playwright 在测试环境补交互证据，本任务不宣称正式验收通过。

## 7. 脚本入口

- 自动化脚本：`dev070-contract.mjs --suite=feature`
- 依赖命令：项目现有 `@vue/compiler-sfc`、`@vue/compiler-dom`、`typescript`
- 结果输出位置：`command-results.md`

## 8. 失败判定

- 原入口被拆成首页常驻双按钮。
- 点击仍直接进入原业务；dialog任一节点存在未审计事件；取消/遮罩/关闭触发业务动作；任一选项夹带额外调用。
