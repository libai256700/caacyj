# AC-PUSH-003 定时发送、取消与失败统计

- 类型：业务-交互级
- 前置条件：管理平台已存在草稿消息、定时消息和至少一条可模拟失败或部分失败的消息任务。
- 业务起点：运营需要安排稍后发送、临时取消或追踪发送失败的消息。
- 触发动作：设置定时发送、在触发前取消消息、查看消息列表与明细中的状态统计和失败原因。
- 关键交互：管理端区分草稿、待发送、发送中、成功、部分失败、失败和已取消；取消后不再继续生成新的投递任务；失败数量、失败原因和重试结果可回看。
- 业务终点：运营能够基于正式状态和统计口径判断消息是否已经发出、是否失败以及是否需要重试。
- 通过条件：立即发送、定时发送、取消发送和失败统计口径完整；状态流转清晰；部分失败不会被错误汇总成全部成功；重试后的最新结果能在统计或明细中承接。
- 核对方式：管理平台状态流转检查、投递明细核对和异常场景回放。
- 证据承接：`061-验收标准/03-测试验证/` 中后续状态流转、任务处理和失败统计证据。
