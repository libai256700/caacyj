# AC-ASSESSMENT-SAVE-201 批次保存状态字段与单向跃迁

- 类型：技术-数据级
- 正式入口：`yj_practice_catalog_batch.status`、分类13/14答案明细持久化事务、各分类既有完成事务，以及 `050-执行脚本/20260831103000-ddl-add_yj_practice_catalog_batch_status.sql`。
- 支撑业务结果：用户在答案长时间写入期间能看到稳定的保存中状态；写入流程无论成功或被服务端捕获为失败，都退出保存中状态，真实业务结果仍完全由原流程判断，DEV-078 不改变 `is_completed`。
- 技术边界：字段固定 `TINYINT NOT NULL DEFAULT 0 COMMENT '评测保存状态：0未开始、1写入中、2写入结束'`；状态2不等于业务完成。历史回填只把 `is_completed=1` 作为只读筛选条件并仅更新 `status=2`。主表 record 在开始答题时已创建，`startBatch` 和主记录插入不得置1；分类13/14均在末题统一提交的第一条答案明细持久化事务内只将 `status` 从0条件更新为1。成功时先完整执行分类13原统一答案保存流程或分类14既有 report-entry 完成流程，再单独只更新 `status=2`。任一答案插入或持久化事务失败时，先回滚原事务并保留原异常，再由不参与原事务的独立事务只补偿 `status=2`；所有 DEV-078 SQL 均禁止更新 `is_completed`。
- 通过条件：新批次默认0；首条答案明细成功后为1；同页幂等重试在1上继续；成功时原完成流程结束后单独置2；持久化失败时原异常继续返回且补偿置2不随原事务回滚；成功置2、失败补偿置2前后的 `is_completed` 值必须一致，证明 DEV-078 未修改该字段。所有置1条件排除2，压力/重试下不存在2回1。幂等SQL兼容人工已建字段，前置检查、仅写status的历史回填、后置校验和按快照回滚口径完整，且本设计阶段无数据库执行记录。
- 证据承接：SQL静态检查、测试库执行前后回执、事务测试、并发/重试状态矩阵和回滚演练记录。
- 当前状态：通过（独立验收）；DEV-078整体待用户审核。
