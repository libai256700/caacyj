# 项目开发与上架交付计划

## 一、项目总览

| 阶段 | 主要工作 | 时间周期 | 交付成果 | 重点说明 |
| --- | --- | --- | --- | --- |
| 资质准备 | 前置梳理产品名称、企业主体、Logo、上架主体、开发者账号、备案资料、协议文件等准备事项 | 待定 | 资质准备清单、材料准备清单、待确认清单 | 本阶段存在较多外部申请和审核流程，很多材料需要提交政府或平台审核，周期通常不可完全控；建议尽早启动，部分事项可提前找对应代理机构协助申请，以提高推进效率。 |
| 需求确认 | 确认项目范围、交付边界、业务场景、交付目标和客户确认项 | 待定 | 需求确认结果、范围说明 | 需以前置确认结果为准。 |
| 合同签署 | 确认合作范围、交付标准、职责分工、验收方式和配合机制 | 待定 | 合同文件、职责分工、交付说明 | 需以前置确认结果为准。 |
| 研发实施 | 完成设计、开发、联调和版本实现 | 待定 | 阶段版本、研发版本 | 需以前置确认结果为准。 |
| 测试验证 | 完成功能测试、兼容测试、稳定性测试和问题修复 | 待定 | 测试版本、问题清单、修复版本 | 需以前置确认结果为准。 |
| 用户验收 | 组织客户验收，确认页面效果、业务流程和交付范围 | 待定 | 验收结果、验收版本 | 需以前置确认结果为准。 |
| 发布上线 | 整理发布资料、提交应用市场、跟进审核反馈并完成发布 | 待定 | 上架资料、发布版本、发布记录 | 需以前置确认结果为准。 |
| 持续运维 | 处理上线后问题、版本更新、资料维护和后续优化支持 | 待定 | 运维记录、更新记录、优化计划 | 按实际运营情况持续安排。 |

## 二、资质准备
| 类别 | 甲方需提供项 | 案例/说明 |
| --- | --- | --- |
| 产品信息 | 产品名称 | 例如：正式名称、简称、英文名。用于应用市场展示、协议文件、备案信息、宣传资料统一口径。 |
| 产品信息 | 产品 Logo | 例如：企业标准 Logo、产品 Logo、APP Logo、透明底版本。用于启动页、应用内品牌位、应用市场资料。 |
| 产品信息 | 产品图标确认意见 | 例如：甲方确认“使用企业主 Logo 作为应用图标”或“单独设计 APP 图标”。这里是确认口径，不是甲方出技术文件。 |
| 产品信息 | APP 图标规范尺寸图 | 例如：应用市场常用 `512x512` 主图标、各平台要求的图标规格图。若甲方没有现成文件，可由我方按确认后的 Logo 协助制作。 |
| 产品信息 | APP 横竖屏应用截图 | 例如：首页截图、核心功能页截图、登录页截图。应用市场提审通常必传，如甲方暂无成品，可由我方基于最终版本协助整理。 |
| 产品信息 | 宣传图/预览视频确认意见 | 例如：是否需要横版宣传图、竖版宣传图、应用预览视频。若平台要求而甲方不便提供，可由我方协助制作基础版素材。 |
| 主体信息 | 企业主体名称 | 例如：营业执照上的完整公司名称。后续上架、备案、协议、软著通常都要与主体保持一致。 |
| 主体信息 | 上架主体名称 | 例如：是用总公司上架，还是用子公司上架。需要甲方明确最终用哪个主体提交应用市场。 |
| 主体信息 | 开发者账号主体 | 例如：Apple 开发者账号主体、各安卓市场开发者账号主体。若甲方已有账号，需提供账号主体信息；若没有，需确认由谁注册。 |
| 主体信息 | 对外展示名称 | 例如：在应用市场、官网、宣传页展示“某某科技”还是“某某品牌”。 |
| 主体信息 | 安卓/iOS 包名确认 | 例如：`com.yunjikeji.flightacademy`。有些甲方会对包名有固定要求，需提前确认，避免后续上架、备案或签名时再改。 |
| 主体信息 | 企业对公账户信息 | 例如：开户名称、开户行、对公账号。开发者账号认证、签约、结算或提现场景常会用到，通常需甲方提供。 |
| 主体信息 | 法人实名信息 | 例如：法人姓名、身份证号、实名手机号。多数企业开发者账号认证时会用到，通常需甲方提供。 |
| 主体信息 | 法人手持证件照 | 例如：法人手持身份证或营业执照照片。很多应用市场企业认证会要求上传，通常需甲方提供。 |
| 主体信息 | 紧急联系人信息 | 例如：联系人姓名、手机号、邮箱。用于平台审核回访、异常通知和紧急沟通，通常需甲方指定。 |
| 主体信息 | 售后责任人信息 | 例如：售后负责人姓名、电话、邮箱。用于用户投诉、平台回访和售后责任确认，通常需甲方指定。 |
| 渠道范围 | 上架渠道范围 | 例如：只上 iOS，还是 iOS + 华为 + 小米 + OPPO + VIVO + 应用宝。 |
| 渠道范围 | 首发地区范围 | 例如：只在中国大陆发布，还是后续也考虑海外地区。 |
| 品牌资料 | 企业介绍 | 例如：公司简介、主营业务、行业定位。用于官网、应用市场、宣传资料。 |
| 品牌资料 | 产品介绍 | 例如：这款产品是做什么的、面向谁、核心价值是什么。用于应用市场介绍和对外说明。 |
| 品牌资料 | 宣传文案 | 例如：一句话介绍、详细介绍、产品卖点。 |
| 品牌资料 | 最终域名/网址 | 例如：企业官网、产品介绍页、后台网址、落地页，如 `https://www.xxx.com`、`https://admin.xxx.com`。很多协议、应用市场资料和后台联调都需要提前明确正式网址。 |
| 品牌资料 | 客服电话 | 例如：400 电话、座机、手机号。用于应用市场和用户联系。 |
| 品牌资料 | 联系邮箱 | 例如：客服邮箱、商务邮箱、投诉邮箱。用于应用市场和协议文件。 |
| 品牌资料 | 版本声明/更新日志口径 | 例如：`V1.0.0 首次发布，包含课程学习、题库练习、个人中心功能`。应用市场提审时通常必填，甲方提供业务口径，我方可协助整理成标准文案。 |
| 合规资料 | 营业执照 | 例如：营业执照扫描件或清晰照片。是证明企业主体身份的基础材料。 |
| 合规资料 | ICP 相关材料 | 例如：已备案网站的 ICP 备案号、备案主体信息、备案截图。通俗理解：证明这个主体在国内有合规的网站/网络信息服务基础。 |
| 合规资料 | 增值电信业务经营许可证 | 例如：`增值电信业务经营许可证`、`EDI`、`ICP 证` 等对应证照信息。通俗理解：如果业务模式涉及经营性互联网信息服务或特定在线业务，通常需要提前判断是否需要该许可证。 |
| 合规资料 | APP 备案信息 | 例如：APP 备案编号、备案主体、备案名称。通俗理解：这是 APP 在国内正式提供互联网信息服务时需要对应的一项备案信息。 |
| 合规资料 | 安全评估报告 | 例如：按全国互联网安全管理服务平台要求整理的安全评估报告。通俗理解：用于说明系统安全管理、数据保护、账号权限、日志留存、应急处置等安全措施的材料。 |
| 合规资料 | 软件著作权 | 例如：`XX系统 V1.0` 的《计算机软件著作权登记证书》。通俗理解：这是证明该软件著作权归属的正式证书，很多正式上架场景会要求提供。 |
| 合规资料 | 商标材料 | 例如：产品名称商标注册证、受理通知书。用于证明名称或品牌归属。 |
| 合规资料 | 品牌授权材料 | 例如：若产品名称、Logo、品牌不在当前上架主体名下，需要提供授权书。 |
| 协议文件 | 隐私政策 | 例如：用户信息收集范围、用途、存储方式、联系方式。应用市场和应用内通常都需要。 |
| 协议文件 | 隐私政策独立网页链接 | 例如：`https://www.xxx.com/privacy`。不能只是本地文档，必须是线上可访问链接；如甲方已有域名，我方可协助部署页面。 |
| 协议文件 | 用户协议 | 例如：用户使用规则、责任边界、服务说明。 |
| 协议文件 | 账号注销流程说明 | 例如：用户如何提交注销申请、注销后数据如何处理、处理时效多久。当前多数应用市场会重点核查。 |
| 协议文件 | 权限使用说明文档 | 例如：相机用于上传头像，定位用于门店定位，存储用于保存图片。安卓应用市场通常要求逐项说明用途；甲方提供业务原因，我方可协助整理。 |
| 协议文件 | 付费/内购说明 | 例如：会员功能、课程购买、充值服务、自动续费规则。如产品存在付费能力，需单独说明。 |
| 协议文件 | 防沉迷说明/适龄提示文案 | 例如：适用年龄范围、学习时长提醒、未成年人使用提示。教育类、内容类产品常需明确。 |
| 协议文件 | 第三方授权说明 | 例如：如果产品内使用了第三方地图、短信、支付、登录服务，需要说明来源和授权情况。 |
| 协议文件 | 内容使用说明 | 例如：如果使用了课程内容、题库内容、图片素材、视频素材，需要说明这些内容是否为甲方自有或已获授权。 |
| 协议文件 | 上架承诺书/内容合规承诺书 | 例如：应用市场要求线上勾选或线下签署的承诺文件。通常需甲方盖章或确认，我方可协助整理模板。 |
| 账号资料 | Apple 开发者账号信息 | 例如：甲方已有 Apple 开发者账号，需确认账号主体、登录邮箱、管理员归属。 |
| 账号资料 | 安卓开发者账号信息 | 例如：甲方已有华为、小米、OPPO、VIVO、应用宝等开发者账号，需确认主体和管理员归属。 |
| 账号资料 | 应用市场后台联系人 | 例如：哪个人负责接收审核短信、邮件、驳回通知。 |

## 三、需求确认
本阶段主要是把“要做什么功能、每个功能具体怎么描述、做到什么程度算完成，以及高保真页面是否确认通过”提前确认清楚，避免项目做到一半再反复改需求。

| 需求条目 | 功能描述 | 验收标准 |
| --- | --- | --- |
| 需求 1 | 甲方填写本条需求要做什么 | 甲方填写这一条做到什么程度算完成 |
| 需求 2 | 甲方填写本条需求要做什么 | 甲方填写这一条做到什么程度算完成 |
| 需求 3 | 甲方填写本条需求要做什么 | 甲方填写这一条做到什么程度算完成 |
| 高保真确认 | 甲方确认高保真页面、交互流程、页面结构、视觉样式是否作为正式开发依据 | 明确高保真确认通过后再进入正式开发，后续如再调整按变更处理 |

## 四、合同签署

本阶段目标是完成商务确认、职责确认和交付确认，为后续实施建立正式依据。

本阶段主要工作：

- 确认合同范围、交付内容、交付周期、费用和验收方式。
- 明确客户方与项目团队的职责分工。
- 明确哪些资料由客户提供，哪些资料由项目团队协助整理。
- 明确上架是否纳入本次交付范围，若纳入，则同步确认上架渠道和资料准备责任。
- 明确后续版本调整、验收反馈和发布配合机制。

本阶段交付成果：

- 合同签署文件
- 职责分工说明
- 交付标准说明

## 五、研发实施

本阶段目标是完成设计、开发和联调，形成可测试、可交付的研发版本。

本阶段主要工作：

- 完成原型整理、视觉设计和页面实现。
- 完成前后端开发、接口联调和基础数据配置。
- 完成正式环境或项目约定环境的基础搭建。
- 预留正式发布所需的产品名称、Logo、协议入口、版本管理等基础能力。

本阶段交付成果：

- 阶段版本
- 研发版本

## 六、测试验证

本阶段目标是完成测试和修复，形成可交付、可验收的稳定版本。

本阶段主要工作：

- 完成功能测试、兼容性测试、稳定性测试。
- 输出问题清单并完成问题修复。
- 对修复后的版本进行回归验证。
- 如后续需要正式上架，同步整理应用包、包名、签名、截图、应用介绍和联系方式等提审基础资料。

本阶段交付成果：

- 测试版本
- 问题清单
- 修复版本
- 提审基础资料

## 七、用户验收

本阶段目标是完成客户验收，确认本次交付内容符合约定。

本阶段主要工作：

- 组织客户进行产品验收，确认页面效果、业务流程和交付范围。
- 记录客户验收意见和调整项。
- 根据验收意见完成必要调整，并形成验收版本。

本阶段交付成果：

- 验收结果
- 验收版本

## 八、发布上线

本阶段目标是完成正式发布和应用市场提审上线。

本阶段主要工作：

- 整理发布资料和上架资料。
- 完成渠道资料录入、提审包整理和提审提交。
- 配合客户补齐正式上架所需资料，包括产品名称、企业主体、Logo、ICP 相关材料、APP 备案、软件著作权、隐私政策、用户协议等。
- 根据审核反馈完成补充材料、文案调整或版本修正。

本阶段交付成果：

- 上架资料
- 发布版本
- 发布记录

## 九、持续运维

本阶段目标是保障产品上线后可持续运行、可持续更新、可持续维护。

本阶段主要工作：

- 处理上线后的异常、反馈、兼容性问题和优化需求。
- 持续进行版本更新、页面优化和内容调整。
- 持续维护应用市场所需资料，确保产品名称、主体信息、协议文件和备案信息保持一致。
- 根据后续业务发展，继续补充商标、版权、资质和渠道扩展等工作。

本阶段交付成果：

- 运维记录
- 更新记录
- 问题处理记录
- 后续优化计划

## 十、职责分工

| 角色 | 主要职责 |
| --- | --- |
| 客户方 | 确认产品名称、企业主体、品牌资料、资质材料、合同内容、验收意见和上架范围 |
| 项目团队 | 负责方案整理、设计研发、测试修复、交付发布和运维支持 |
| 法务行政 | 配合提供营业执照、备案材料、软件著作权、协议文件等正式资料 |
| 渠道运营 | 配合处理开发者账号、应用市场资料录入、提审提交和反馈跟进 |
