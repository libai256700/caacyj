# 岗位采集结果 API 对接指南

> 更新时间：2026-08-19
> 阅读对象：已经完成岗位采集，只负责将结果写入小技系统的智能体。
> 本文只描述系统对接，不包含岗位采集、网页解析、渠道选择或数据库实现。

## 1. 对接目标

智能体对每条已采集岗位完成以下闭环：

1. 将采集结果转换为系统字段。
2. 校验字段格式和长度。
3. 查询系统中是否已存在同一岗位。
4. 不存在时新增，已存在且内容变化时更新，无变化时跳过。
5. 写入后回查，确认数据保存正确。
6. 输出本批次对接结果。

禁止直接连接数据库、调用删除接口，或在代码、日志和报告中输出 Token、密码等凭据。

## 2. 接入配置

运行环境必须通过安全变量注入以下配置：

```text
YJ_API_BASE_URL=https://yunjikeji.lai-do.com/yunjikeji-admin-api
YJ_ACCESS_TOKEN=<通过安全渠道注入>
YJ_REFRESH_TOKEN=<通过安全渠道注入>
YJ_TENANT_ID=<租户 ID>
```


### 2.1 对接账号信息

| 项目 | 值 |
| --- | --- |
| 对接账号 | `jobagent` |
| 租户 ID | `1` |
| 账号用途 | 仅用于岗位采集结果 API 对接 |
| 管理员角色 | 无 |

访问令牌和刷新令牌不写入本文。交接给其他智能体时，必须通过其运行环境的安全变量注入：

```text
YJ_ACCESS_TOKEN=<通过安全渠道单独提供>
YJ_REFRESH_TOKEN=<通过安全渠道单独提供>
YJ_TENANT_ID=1
```

当前开发机上的凭据文件为 `.env.job-agent`，该文件已被 Git 忽略并限制为当前 Windows 用户和 `SYSTEM` 可读。跨机器交接时不要复制到公开目录、代码仓库、普通附件或提示词中；应由系统负责人通过 Secret Manager、CI/CD Secret、容器 Secret 或智能体平台的安全变量功能注入。

账号密码不作为文档内容保存。若访问令牌和刷新令牌均失效，应由系统管理员重置 `jobagent` 账号密码并重新签发令牌。

所有请求使用以下请求头：

```http
Authorization: Bearer ${YJ_ACCESS_TOKEN}
Content-Type: application/json
tenant-id: ${YJ_TENANT_ID}
```

仅当 `YJ_TENANT_ID` 非空时发送 `tenant-id`。

## 3. 成功判断

服务端标准响应：

```json
{
  "code": 0,
  "msg": "",
  "data": {}
}
```

每次请求必须同时检查 HTTP 状态码和响应体：

- HTTP 请求成功且 `code = 0`：业务成功。
- `code = 401`：令牌无效或已过期，需要刷新令牌后重试一次。
- 其他 `code`：业务失败，记录脱敏后的错误信息，不得视为成功。

刷新访问令牌：

```http
POST ${YJ_API_BASE_URL}/admin-api/system/auth/refresh-token?refreshToken=${YJ_REFRESH_TOKEN}
```

刷新成功后，使用响应中的新 `accessToken`；若返回新的 `refreshToken`，也应同步替换运行环境中的旧值。禁止在日志中输出完整令牌。

## 4. 岗位字段

上传前将每条采集结果转换为以下结构：

```json
{
  "name": "无人机教员",
  "company_name": "示例航空科技有限公司",
  "source_code": "liepin",
  "external_post_id": "source-job-123456",
  "salary_range": "8-12K",
  "work_area": "武汉市洪山区",
  "publish_date": "2026-08-19",
  "detail_url": "https://example.com/jobs/source-job-123456",
  "status": true
}
```

| 字段 | 是否必需 | 格式与限制 |
| --- | --- | --- |
| `name` | 必填 | 岗位名称，最多 100 字符 |
| `company_name` | 建议必填 | 企业名称，最多 100 字符 |
| `source_code` | 必填 | 来源编码，最多 10 字符 |
| `external_post_id` | 强烈建议必填 | 来源平台稳定岗位 ID，最多 100 字符 |
| `salary_range` | 可空 | 薪资原始含义，最多 100 字符 |
| `work_area` | 可空 | 工作地区，最多 100 字符 |
| `publish_date` | 可空 | `YYYY-MM-DD`，未知时传 `null` |
| `detail_url` | 建议必填 | 岗位详情绝对 URL，最多 500 字符 |
| `status` | 必填 | 有效岗位固定传 `true` |

当前可安全使用的 `source_code`：

```text
guopin
liepin
zhilian
51job
```

暂时不要上传 `source_code = boss_zhipin`，该值超过当前字段长度。其他来源编码必须先由系统负责人确认后再上传。

字段转换要求：

- 删除字符串首尾空白、HTML 标签和不可见字符。
- 连续空白归一为一个空格。
- 不得用随机值或本次执行时间替代 `external_post_id`。
- 未知发布时间传 `null`，不得用采集时间代替。
- URL 使用绝对地址，保留能稳定访问岗位详情所需的参数。

## 5. 对接步骤

### 第一步：验证认证

调用岗位分页接口读取一条数据：

```http
GET ${YJ_API_BASE_URL}/admin-api/postcollect/post/page?pageNo=1&pageSize=1
```

只有 HTTP 成功且响应体 `code = 0`，才能开始本批次写入。

### 第二步：校验待上传数据

逐条检查第 4 节字段规则。字段缺失、超长、日期格式错误或来源编码不受支持时，不调用写入接口，直接记录为失败项。

### 第三步：查询是否已存在

有稳定外部岗位 ID 时调用：

```http
GET ${YJ_API_BASE_URL}/admin-api/postcollect/post/page?pageNo=1&pageSize=200&source_code={source_code}&external_post_id={external_post_id}
```

服务端分页查询可能是模糊匹配。智能体必须在 `data.list` 中再次进行精确比较，只有 `source_code` 和 `external_post_id` 都完全相同，才是同一岗位。

没有 `external_post_id` 时，使用以下降级键查重：

```text
source_code + name + company_name + work_area
```

降级查重必须在报告中标记为 `weak_identity`。同一 `source_code` 的写入并发数建议为 1，最高不得超过 3。

### 第四步：新增、更新或跳过

查询不到相同岗位时新增：

```http
POST ${YJ_API_BASE_URL}/admin-api/postcollect/post/create
```

请求体为第 4 节的完整岗位对象。成功时 `data` 是新岗位 ID。

查询到相同岗位时：

- 字段完全一致：不写入，记录为 `skipped`。
- 展示字段发生变化：调用更新接口。

```http
PUT ${YJ_API_BASE_URL}/admin-api/postcollect/post/update
```

更新请求体必须带系统中的岗位 `id`，并提交完整的最新岗位字段：

```json
{
  "id": 946,
  "name": "无人机教员",
  "company_name": "示例航空科技有限公司",
  "source_code": "liepin",
  "external_post_id": "source-job-123456",
  "salary_range": "10-15K",
  "work_area": "武汉市洪山区",
  "publish_date": "2026-08-19",
  "detail_url": "https://example.com/jobs/source-job-123456",
  "status": true
}
```

成功时响应 `data = true`。

### 第五步：写入后回查

对每条新增或更新记录调用：

```http
GET ${YJ_API_BASE_URL}/admin-api/postcollect/post/get?id={岗位ID}
```

确认以下字段与上传值一致：

```text
name
company_name
source_code
external_post_id
salary_range
work_area
publish_date
detail_url
status
```

新增请求结果不确定时，不得立即再次新增。先按幂等键重新查询，确认不存在后才可重试，避免重复岗位。

### 第六步：输出对接报告

每批完成后输出：

```json
{
  "started_at": "2026-08-19T14:00:00+08:00",
  "finished_at": "2026-08-19T14:03:12+08:00",
  "received": 20,
  "valid": 18,
  "created": 8,
  "updated": 3,
  "skipped": 7,
  "weak_identity": 0,
  "failed": 2,
  "created_ids": [946, 947],
  "failures": []
}
```

失败项至少包含：来源编码、外部岗位 ID、失败阶段、错误码和脱敏后的错误信息。报告不得包含 Token、密码、Cookie 或完整认证请求。

## 6. 重试规则

| 场景 | 处理方式 |
| --- | --- |
| 网络超时、连接中断 | 等待 2、5、15 秒，最多重试 3 次 |
| HTTP 429、502、503、504 | 指数退避，最多重试 3 次 |
| `code = 401` | 刷新 Token，原请求最多重试 1 次 |
| 字段校验失败 | 不重试，记录具体字段错误 |
| 来源编码不支持 | 不重试，提交系统负责人处理 |
| 新增结果不确定 | 先查重，确认不存在后再重试 |

单条岗位失败时继续处理后续数据。出现以下任一情况时停止整个批次：

- 认证持续失败。
- 服务连续不可用。
- 本批次错误率超过 20%。

## 7. 对接验收

正式批量写入前，按以下顺序验证：

1. 使用 1 条真实采集结果完成查询、新增和回查。
2. 再次上传同一条数据，结果必须为跳过，不能新增重复岗位。
3. 修改该岗位的薪资或地区后再次执行，必须更新原记录。
4. 使用 5 条真实结果验证混合的新增、更新和跳过流程。
5. 确认执行报告计数与接口处理结果一致。
6. 验证通过后，再处理完整岗位批次。

## 8. 最短执行清单

```text
1. 加载安全变量
2. 调用分页接口验证 Token
3. 转换并校验岗位字段
4. 按幂等键查询现有岗位
5. 执行 create / update / skip
6. 对 create / update 逐条回查
7. 输出脱敏的对接报告
```
