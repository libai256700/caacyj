# 飞书岗位文档采集工作流设计

> 状态：已按公开链接方案实现，待测试环境验收
> 更新时间：2026-08-20
> 目标：将飞书岗位信息目录作为岗位采集的唯一运行来源。

## 1. 目标来源

飞书目录：

<https://zcn5jf36q4fv.feishu.cn/drive/folder/FhmNfRifQlpsZldRXKMcwvKlnCg>

当前目录名称为“岗位信息报告”，目录内是按日期生成的岗位日报文档。已确认文档内容包含岗位名称、企业、薪资、地区、原始招聘平台和岗位详情链接等信息。

## 2. 运行规则

新的任务类型使用：

```text
collection_channel=feishu_folder
collection_key=<飞书 folder_token>
```

任务每次执行时按以下顺序运行：

1. 获取目标目录下的文件清单，处理分页，不只读取第一页。
2. 只处理可读取的新版文档 `docx`；其他文件类型记录为跳过，不进入岗位入库。
3. 使用 `document_id` 和完整正文 SHA-256 匹配本地同步记录。
4. 对从未处理或正文已变化的文档读取完整正文。
5. 将完整正文一次性交给岗位提取 AI，由 AI 理解文档结构并只提取“新增岗位（今日首次出现）”。
6. 校验 AI 返回的 JSON 结构和必要字段，然后将岗位逐条新增到正式岗位表。
7. 将数据库生成的正式岗位 ID 按顺序回写到文档岗位明细；全部写入成功后才标记文档已采集。
8. 保存执行统计、文档状态、岗位明细和失败原因，供后台查看。

文档没有变化时不重复调用 AI。文档发生变化时，按新的 `revision_id` 或内容哈希重新处理，并保留历史执行记录。

## 3. “是否已采集”标识

新增文档同步表 `yj_feishu_post_document`，建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `tenant_id` | 租户 ID |
| `folder_token` | 目标目录标识 |
| `document_id` | 飞书新版文档标识 |
| `document_name` | 文档名称 |
| `document_url` | 文档地址 |
| `document_revision_id` | 最近一次读取的版本号 |
| `content_hash` | 最近一次读取内容的 SHA-256 |
| `collected` | 是否已完成本次采集，`false/true` |
| `status` | `NEW`、`PROCESSING`、`COLLECTED`、`PARTIAL_FAILED`、`FAILED`、`SKIPPED` |
| `last_run_id` | 最近一次执行实例 ID |
| `last_error` | 脱敏后的失败原因 |
| `collected_at` | 完成采集时间 |
| `create_time` / `update_time` | 审计时间 |

唯一键：

```text
tenant_id + folder_token + document_id
```

`collected=true` 只允许在 AI 提取成功且所有岗位均已写入并取得正式岗位 ID 后设置。AI 解析失败或岗位入库失败时，不能误标记为已采集。AI 返回空岗位数组时记录为 `NO_JOBS`，该正文版本不再重复处理。

文档岗位明细表 `yj_feishu_post_document_item` 保存文档内的岗位身份、AI 原始结果摘要、标准化结果、目标岗位 ID、处理状态和错误原因，供后台展示每篇文档本次新增了哪些岗位。

## 4. 公开链接读取

该目录和其中的文档已经验证为公开可读，匿名浏览器不登录、不携带 Cookie 也能：

1. 打开目标目录。
2. 读取目录下的文档链接和文档名称。
3. 继续加载目录分页或滚动后的文档。
4. 打开 `docx` 文档并读取正文。

因此本流程不使用飞书 App ID、App Secret、`tenant_access_token` 或甲方账号登录态。服务端通过独立的无 Cookie 浏览器上下文执行，不能复用开发人员浏览器的 Cookie、LocalStorage 或登录会话。

当前实现使用飞书公开目录接口和公开文档页面：

```text
创建一次匿名 HTTP 会话
访问 FEISHU_FOLDER_URL 建立飞书匿名访客会话
调用公开目录分页接口，收集所有 /docx/{document_id}
逐个读取公开文档页面并提取完整正文
任务结束后销毁会话
```

运行配置只需要公开目标地址：

```text
FEISHU_FOLDER_URL=https://zcn5jf36q4fv.feishu.cn/drive/folder/FhmNfRifQlpsZldRXKMcwvKlnCg
```

公开链接失效、页面要求登录、文档不可读或页面结构变化时，任务应失败并报警，不能尝试读取用户浏览器会话，也不能绕过访问限制。

## 5. AI 结构化提取

AI 只负责把完整文档转换为岗位对象，不负责直接写数据库。要求返回严格 JSON：

```json
{
  "jobs": [
    {
      "name": "无人机教员",
      "company_name": "示例航空科技有限公司",
      "source_code": "zhilian",
      "external_post_id": "CCL1231623410J40444271107",
      "salary_range": "7000-14000",
      "work_area": "西安",
      "publish_date": null,
      "detail_url": "https://example.com/job/123",
      "status": true
    }
  ],
  "ignored": [],
  "warnings": []
}
```

提取约束：

- 只使用文档中出现的事实，不得补写企业、薪资、地区或 URL。
- AI 必须自行理解文档结构，只提取“新增岗位（今日首次出现）”部分，并在输出前自行复核完整性和重复项。
- 每篇文档只调用一次 AI：将完整正文交给模型，由模型结合语义和上下文识别“今日新增/今日首次出现”的岗位集合并输出岗位 JSON。后端不切章节、不生成辅助行号，也不使用固定标题、编号、分隔符或正则规则判断岗位范围。
- 不同日报的标题和排版可能变化，模型必须排除更新岗位、持续在招、历史岗位、汇总说明和其他章节内容；无法确认今日新增岗位时返回空 `jobs` 数组。
- 缺失字段传 `null`，不能使用随机值或采集时间代替。
- 从详情 URL 或文档标注识别原始招聘平台，写入 `source_code`。
- 无法识别平台时使用 `feishu` 作为来源，并保留原始详情链接；正式启用前由系统确认来源字典。
- `external_post_id` 优先取原始平台岗位 ID；没有时使用 `feishu:<document_id>:<item_index>`，保证稳定且不超过字段长度。
- AI 输出必须先通过 JSON 解析和字段长度校验，失败时进入 `PARTIAL_FAILED` 或 `FAILED`，不能直接写入。
- 后端不读取文档声明的新增数量，不把该数量与 `jobs` 数组长度比较，也不因数量差异触发重试或失败；岗位完整性由 AI 提取过程保证。
- 后端仅在 AI 返回空内容、非 JSON、缺少 `jobs` 数组或岗位缺少必要字段时进行一次技术性重试；日报标题中的日期由后端解析并覆盖所有岗位的 `publish_date`。

## 6. 入库和增量处理

AI 输出沿用岗位 API 对接规范：


1. AI 返回的每条岗位直接新增到正式岗位表，不在本环节执行岗位字段去重或更新。
2. 前置日报生产环节负责保证“新增岗位（今日首次出现）”内容已完成去重。
3. 岗位新增后直接取得数据库生成的岗位 ID。
4. 将岗位 ID 按本次提取顺序写回 `yj_feishu_post_document_item`。
5. 任一岗位未取得正式岗位 ID 时，本次运行标记为部分失败或失败，不能误报成功。

读取幂等边界是“飞书目录链接记录”：每次任务只读取目录清单；如果 `folder_token + document_id` 已存在未删除的读取记录，则直接跳过，不请求文档正文、不调用 AI。需要重新读取时，先删除该文档的历史读取记录；下一次任务发现该链接没有有效记录后，才重新请求正文、提取岗位并恢复原记录。

## 7. 任务实例和报告

沿用现有 `yj_post_collection_task_instance` 记录任务运行状态，同时扩展执行结果：

```json
{
  "collection_channel": "feishu_folder",
  "folder_token": "<redacted>",
  "documents_seen": 40,
  "documents_new": 3,
  "documents_collected": 2,
  "documents_partial_failed": 1,
  "jobs_extracted": 192,
  "jobs_created": 8,
  "jobs_updated": 3,
  "jobs_skipped": 176,
  "jobs_failed": 5
}
```

日志只输出文档 ID 的脱敏值、岗位数量、阶段和错误类型，不输出 Cookie、登录态、页面全文或其他会话数据。

## 8. 旧渠道处理

旧的 BOSS、猎聘、智联、国聘、前程无忧定时任务全部停用。当前环境已完成：

- 智联招聘任务：停用
- 猎聘任务：停用
- 国聘任务：停用
- BOSS 直聘任务：原已停用
- 前程无忧任务：原已停用

代码层面新增飞书工作流后，应将 `feishu_folder` 作为唯一允许的自动采集渠道；旧平台采集器保留代码但不得被调度器自动执行，避免影响历史数据和回滚能力。

## 9. 开发顺序

1. 验证飞书目录和文档公开可读。
2. 新增匿名飞书目录文件清单客户端和新版文档读取客户端。
3. 新增文档同步表、岗位明细表及 Mapper。
4. 新增 `feishu_folder` 采集服务和任务实例状态流转。
5. 接入现有 AI 客户端，增加岗位 JSON Schema 校验。
6. 接入岗位直接新增和正式岗位 ID 回写逻辑。
7. 用目录中 1 篇真实文档完成闭环，再扩大到 3 篇，最后启用定时任务。
8. 增加重复执行、文档更新、AI 失败、单条岗位失败和 Token 过期测试。

## 10. 开发前确认项

公开链接方案不需要甲方额外提供飞书应用凭据。开发前只需确认：

- 公开链接持续允许匿名查看目录和文档。
- 目录内新增文档仍使用可读取的新版文档格式。
- AI 模型使用现有服务端配置，还是为岗位提取单独指定模型。
- 文档更新后是否需要重新解析并更新原岗位。
