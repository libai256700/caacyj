## 2. 任务目标

1. 基于用户提供的 `ServiceException: 自测报告生成失败，请稍后重试` 真实样本，定位自测报告生成失败的真实入口、调用链和根因。
2. 在不扩大到三方目录或无关业务的前提下修复根因，并验证自测完成后报告可生成、可查询且失败分支有明确证据。

## 3. 任务范围

- 包含：异常附件解析、前后端自测报告生成调用链核对、真实报告生成入口的方法名与入参日志、可单独执行的 Test 调用方法、失败页“重新生成自测报告”按钮、基于 `yj_assessment_result` 归属记录恢复生成参数并重调真实生成方法、报告记录状态与结果字段回写、运行日志/接口/数据状态证据收集、必要的最小代码修复、针对性测试和独立验收证据。
- 不包含：生产数据库直接写操作、猜测连接/账号/环境、修改 `uni_modules/**`、与报告生成无关的页面或题库重构。

## 4. 统一原则

- 先读任务详情：阶段任务总表只做导航；真正实施前，必须先阅读对应任务详情。
- 计划启动门禁：只要 `01-验收标准.md` 未收口、阶段任务总表未补齐或当前任务没有任务详情，任何实施任务都不得进入 `进行中`。
- 正式验收承载位置：正式验收标准统一写到 `01-验收标准.md`；`00-任务计划.md` 只保留验收入口和状态门禁，不平行定义第二套正式验收标准。
- 未通过场景门禁：只要正式验收项仍有 `未通过`，不得把任务状态改为 `已完成`。
- 人工审核门禁：只有“独立验收通过 + 用户明确审核通过”同时满足后，才允许执行归档和状态回写。

### TASK-003 梳理异常样本与源码调用链并修复根因

**实施标准**
- 先读取异常附件并确认环境、触发入口、时间点、请求路径和流程标识；再按“页面入口 -> 报告接口 -> 服务层 -> 异步/存储”逐段核对，不以统一错误文案直接归因。
- 在自我测评最后一步的真实报告生成入口输出可定位日志，至少包含入口方法名和实际入参；日志必须复用项目现有日志框架并对 Token、密码、手机号、身份证号等敏感字段脱敏。
- 在现有测试工程中新增可单独执行的 Test 调用方法，直接调用真实报告生成入口并输出方法名、构造入参及调用结果，不另造假入口，不修改生产契约。
