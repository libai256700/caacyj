# T0004 实施记录

## 1. 信息收集结论

- app 端页面路径：`code/develop/yunjikeji/src/pages/jobs.vue`。
- 页面路由：`code/develop/yunjikeji/src/pages.json` 中 `pages/jobs`。
- 前端接口封装：`code/develop/yunjikeji/src/services/jobs.ts`，接口路径 `/app-api/yj/posts`。
- 实施前事实：页面 `loadJobs()` 调用 `fetchAllJobPosts({ status: true })`，会循环拉取全量岗位，不符合触底分页加载要求。
- 后端入口：`FrontPostController#getPostPage(@Valid AppPostPageReqVO reqVO)`。

## 2. 实施改动

- 提交：`ac05143b feat: app岗位列表支持分页刷新`。
- `code/develop/yunjikeji/src/pages/jobs.vue`
  - 岗位列表由 `fetchAllJobPosts` 改为 `fetchJobPostPage`。
  - 首屏加载传入 `pageNo=1`、`pageSize=10`、`status=true`。
  - 增加 `pageNo`、`pageSize`、`hasMore`、`isLoadingMore`、`isRefreshing`、`isLoadingFirstPage` 状态，防止重复请求并处理无更多数据。
  - `onReachBottom` 请求下一页并追加到列表。
  - `onPullDownRefresh` 请求第 1 页并重置列表，结束时调用 `uni.stopPullDownRefresh()`。
- `code/develop/yunjikeji/src/services/jobs.ts`
  - `fetchJobPostPage` 默认 `pageSize` 从 20 改为 10。
  - 保留 `fetchAllJobPosts`，避免影响其他潜在全量场景。
- `code/develop/yunjikeji/src/pages.json`
  - `pages/jobs` 开启 `enablePullDownRefresh`。

## 3. 后端适配结论

- 后端不需要为本次分页需求做核心适配。
- `AppPostPageReqVO extends PageParam`，`PageParam` 默认 `pageNo=1`、`pageSize=10`，并校验页码和每页条数范围。
- `FrontPostServiceImpl#getPostPage` 使用 `postCollectMapper.selectPage(reqVO, wrapper)` 执行分页查询，并返回 `PageResult<AppPostRespVO>`，包含 `list` 与 `total`。
- `PostCollectMapper extends BaseMapperX<PostCollectDO>`，复用框架分页能力。
