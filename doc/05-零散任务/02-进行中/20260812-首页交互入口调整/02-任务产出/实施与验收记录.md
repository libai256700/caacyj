- 根因分类：浏览器登录态下初次 `/yj/customer-auth/me` 当前存在约 20 秒超时且无 HTTP 响应；无登录态对照请求可快速返回，现有证据不足以继续下探后端根因，因此本轮不改后端、不伪装接口已恢复。前端实际硬阻断来自资料保存成功后再次强制调用 `fetchCurrentCustomer()`，二次回读失败会使 `profileVerified`、答题阶段切换和题目加载均无法执行。
- 前端止损：`self-test-answer.vue` 已成组移除身份证号的字段配置、联合类型、表单/触碰状态、格式及校验位校验、重置、资料回填和 `saveCustomerInfo` payload，不保留隐藏提交；资料页只剩姓名、只读手机号、毕业院校（选填）、专业（选填）。
- 请求时序：页面初次加载仍调用一次 `fetchCurrentCustomer()` 用于资料回填，失败时保留登录会话手机号、提示用户并允许手填；点击“下一步”后，`saveCustomerInfo` 成功响应即设置资料已验证、切换答题阶段并调用 `fetchAssessmentQuestions()`，不再发起保存后的第二次 `/me`。保存失败继续停留资料页，保存锁仍阻止重复点击。
