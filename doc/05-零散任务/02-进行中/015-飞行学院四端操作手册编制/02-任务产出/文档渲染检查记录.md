## 2. 渲染方式

1. 先执行 documents 技能提供的规范渲染器 `render_docx.py`。
2. 当前机器未安装 LibreOffice，规范渲染器因找不到 `soffice.exe` 无法完成转换。
3. 按技能规定的回退路径，通过 `Word.Application` 兼容 COM 接口以只读方式打开 DOCX 并导出 PDF；本机实际注册的 PDF 创建程序显示为 WPS 文字。
4. 使用运行时自带 Poppler，以 150 DPI 将 PDF 转为 PNG，输出尺寸统一为 1275 x 1650 像素。

规范渲染器失败仅由本机缺少 LibreOffice 引起，不是文档内容或结构错误。临时 PDF 在检查完成后删除，仅保留逐页 PNG 作为渲染证据。

## 3. 结构检查

- 四册均为 Letter 纵向纸张，四边页边距均为 1 英寸。
- 正文章节使用真实 Word `Heading 1`、`Heading 2`、`Heading 3` 样式。
- 列表使用 Word 原生编号；所有正文实际引用的编号实例均设置 `startOverride=1`，各独立步骤组从 1 重新开始。
- 所有表格均为固定布局和固定列宽，没有依赖自动适应产生的宽度漂移。
- 图片数量与 Markdown 源文件一致，且所有图片均写入替代文本。
- 文档正文未发现手机号、测试密码、TODO、TBD、待补充或待完善等占位内容。
- 构建器的源文档覆盖检查、图片数量检查、表格数量检查均通过。

## 5. 返工记录

1. 首次渲染发现不同步骤组之间的编号会继续累加。
2. 构建器为每个编号实例增加 `w:lvlOverride/w:startOverride=1` 后，重新生成并渲染四册，编号复验通过。
3. 首次视觉检查发现学员登录截图包含测试手机号和验证码；随后对源图执行不可逆脱敏，并同步脱敏两张教员端截图。
4. 源图覆盖后重新生成四册，重新渲染学员端和教员端，并对受影响页面及全量页数、尺寸、空白页和页边界重新检查，结果通过。
