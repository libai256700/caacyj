# 教员端与管理平台功能盘点

## 1. 盘点口径与结论

本文作为《教员端操作手册》和《管理平台操作手册》的事实输入，盘点范围为以下三个工程及当前版本正式文档：

- App 前端：`code/develop/yunjikeji`
- 管理平台前端：`code/develop/yunjikeji-admin-ui`
- 管理平台后端：`code/develop/yunjikeji-admin-server`
- 当前任务计划：`doc/05-零散任务/02-进行中/015-飞行学院四端操作手册编制/00-任务计划.md`
- 当前验收标准：`doc/05-零散任务/02-进行中/015-飞行学院四端操作手册编制/01-验收标准.md`

核心结论：

1. 当前没有独立“教员端”工程、独立教员登录按钮或独立教员路由集。教员使用 App 的“企业登录”入口，后台岗位编码包含 `WT` 时识别为教员岗位。
2. 教员登录后的主操作区为“首页、客服、我的”三个底部入口，核心职责是审核学员加入申请、与已审核通过的学员沟通，以及查看本人和所属组织信息。
3. 管理平台使用后端动态菜单和按钮权限。代码目录中存在的页面不等于某个账号一定可见，手册截图和菜单层级必须以正式账号登录后的实际页面为准。
4. 管理平台项目业务功能集中在首页统计、企业与学员审核、练习与自测、岗位与采集、协议、知识库与智能体、客服会话等模块；标准系统管理页面包括租户、部门、用户、角色和菜单管理。
5. 当前未获得正式管理账号、教员账号、验证码或其他鉴权材料，也未在本子任务中执行会改变真实数据的审核、发布、采集、同步、删除等动作。因此操作结果说明以代码契约为依据，最终手册必须补真实账号的页面截图和只读/可回退验证。

## 2. 教员端身份与进入条件

### 2.1 正确入口

App 登录页只提供两个身份页签：

- 学员登录
- 企业登录

教员必须选择“企业登录”。手册不得写成点击“教员登录”，也不得设计不存在的教员身份切换入口。

企业账号登录成功后，App 查询该手机号对应的后台用户和岗位编码。岗位编码中只要包含 `WT`（不区分大小写），后端返回 `hasWtPost=true`；前端据此使用教员对应租户上下文。最终统一进入 `/pages/home`，再根据企业身份进入 `/pages/enterprise/students`。

### 2.2 使用前置条件

教员账号可正常使用的业务前置条件应在手册“使用前准备”中明确：

1. 手机号已经在当前租户中关联到后台用户。
2. 该用户至少关联一个岗位编码包含 `WT` 的岗位。
3. 手机号与后台用户的匹配在当前租户中必须唯一。
4. 账号、租户、岗位或验证码异常时，应由管理员核对正式账号记录，不能反复尝试其他租户或猜测验证码。

### 2.3 登录后的底部导航

企业/教员身份只展示三个底部入口：

| 导航 | 路径 | 主要用途 |
| --- | --- | --- |
| 首页 | `/pages/enterprise/students` | 查看并处理学员加入申请 |
| 客服 | `/pages/service/customer-service` | 查看已审核通过学员并进入沟通会话 |
| 我的 | `/pages/profile` | 查看本人、手机号、所属组织及账号相关入口 |

“练习”“考试”“岗位”等学员端能力不属于教员底部导航。“教员考试”是学员侧的一种考试模式，不是教员账号的出题、监考或阅卷功能，不能写入教员手册。

## 3. 教员端功能与操作路径

### 3.1 学员加入审核

页面入口：登录后默认首页，或点击底部“首页”。

页面能力：

- 展示学员加入申请列表。
- 支持按学员昵称或手机号检索。
- 支持按申请时间范围筛选。
- 显示待审核、已通过、已拒绝等状态。
- 待审核记录提供“同意”和“拒绝”操作。
- 操作处理中按钮显示“处理中”，避免重复提交。

建议手册步骤：

1. 进入“首页”，先查看申请状态和申请时间。
2. 需要定位特定学员时，输入昵称或手机号；需要核对某一时间段申请时，设置开始时间和结束时间。
3. 核对学员信息、申请时间和目标企业无误后再处理。
4. 接受申请时点击“同意”；拒绝申请时点击“拒绝”。
5. 等待按钮从“处理中”恢复，并确认记录状态变为“已通过”或“已拒绝”。

业务结果：

- “同意”或“拒绝”会调用企业侧学员审核接口并写入真实审核状态。
- 审核通过的学员随后可出现在教员“客服”学员列表中。
- 审核动作会影响学员与企业的业务关系，应在确认申请人和企业无误后执行。

接口契约：

- 列表：`GET /app-api/yj/company/student-audit/page`
- 审核：`PUT /app-api/yj/company/student-audit/audit`

### 3.2 学员沟通列表

页面入口：点击底部“客服”。

教员身份下，该页不是单一“小技客服”入口，而是已审核通过学员的会话列表。页面展示学员姓名、最近消息、最近消息时间和未读数；无数据、加载失败和加载中均有独立状态。

列表分页规则：

- 每页固定请求 50 名学员。
- 页面底部显示“上一页”“第 N 页”“下一页”。
- 第一页不可点击“上一页”。
- 当前页返回不足 50 条时，不再允许进入下一页。
- 加载失败时显示错误提示，可点击重试。

建议手册步骤：

1. 进入“客服”，等待学员列表加载完成。
2. 通过学员姓名、最近消息和未读数判断需要处理的会话。
3. 学员较多时使用“上一页”“下一页”切换，不要把第二页以后误认为没有学员。
4. 点击学员卡片进入会话。
5. 会话加载失败时返回列表后重试；仍失败时记录学员、时间和提示信息交管理员排查。

### 3.3 与学员进行文本、图片和视频沟通

会话页支持：

- 加载历史消息。
- 发送文本消息。
- 从本地选择并发送图片。
- 选择并发送视频。
- 点击图片预览。
- 播放会话中的视频。
- 使用 WebSocket 接收实时消息；实时链路异常时保留接口回退和错误提示。

已有会话会复用原会话；学员尚无会话时，页面在第一次发送前显式创建会话，再发送消息。手册不得要求教员先寻找或创建一个不存在的“新建会话”按钮。

建议手册步骤：

1. 进入目标学员会话，先核对页面上的学员身份和历史消息。
2. 文本沟通时，在输入框填写内容后点击发送，等待消息出现在会话区。
3. 发送图片或视频时，点击对应媒体入口，从设备中选择文件，等待上传和发送完成。
4. 发送后检查消息类型和内容是否正确；涉及隐私、证件或企业内部资料时不得随意上传。
5. 消息长时间未出现或显示实时连接异常时，不要连续重复发送；先返回列表确认最近消息，再按错误提示处理。

### 3.4 “我的”页面

教员身份下，“我的”页面展示：

- 姓名/昵称。
- 脱敏手机号。
- 所属组织或部门。

当前菜单入口为：

- 注销账号。
- 联系客服。
- 隐私协议。
- 关于小技。
- 退出登录。

“账号安全”对应的页面代码目前被注释，不能在手册中写成可点击能力。企业身份也不允许编辑头像，手册不得出现“点击头像修改头像”的步骤。

退出登录建议步骤：

1. 进入底部“我的”。
2. 点击“退出登录”。
3. 按页面确认提示完成退出。
4. 确认回到登录页，避免共用设备保留登录状态。

姓名和部门的真实数据展示仍在当前正式迭代链中。最终截图时必须核对页面实际显示的是后台真实姓名/部门，而不是默认昵称、历史缓存或“暂未绑定”等回退文案。

## 4. 管理平台登录、菜单与退出

### 4.1 入口与运行状态

已确认入口：

- 测试管理端：`https://yunjikeji.lai-do.com/yunjikeji-admin/`
- 测试 API：`https://yunjikeji.lai-do.com/yunjikeji-admin-api`
- 本地管理前端默认端口：`3000`
- 本地后端：`http://127.0.0.1:48080`

本次盘点时，测试管理端入口与测试 API 可达性检查为 HTTP 200，本地后端 `/actuator/health` 为 HTTP 200；本地 `3000` 端口未启动，App H5 使用 `5173`。可达性只说明入口响应正常，不代表登录账号、动态菜单及每个业务接口均已验收。

### 4.2 登录字段

登录表单根据环境配置展示以下内容：

- 租户名称：仅在多租户开关开启时显示。
- 用户名。
- 密码，可切换显示/隐藏。
- 记住我，当前默认勾选。
- 忘记密码。
- 验证码：仅在验证码开关开启时显示，当前代码默认验证码类型为滑块拼图。
- 登录按钮。

建议手册步骤：

1. 打开正式或测试管理端地址，确认域名和环境无误。
2. 若页面显示租户字段，填写管理员提供的正式租户名称。
3. 填写用户名、密码，并按页面要求完成验证码。
4. 共用电脑应取消“记住我”；个人受控设备可按单位安全要求决定是否勾选。
5. 点击登录，等待“正在加载系统中”结束并进入首页。
6. 登录后先核对右上角用户名和左侧菜单是否符合本人职责；菜单缺失时由管理员检查角色和菜单分配，不要切换未知租户或借用他人账号。

### 4.3 动态菜单和按钮权限

登录后前端调用 `/system/auth/get-permission-info` 获取用户信息、角色、按钮权限和菜单。`userInfo.menus` 被写入 `ROLE_ROUTERS`，再由权限模块生成实际路由。

因此：

- `src/views` 中存在的页面不等于当前账号一定能看见。
- 同一操作手册中的左侧菜单名称和层级，必须以正式截图账号实际下发结果为准。
- 页面按钮普遍使用 `v-hasPermi` 控制，例如用户新增、导入、导出、删除，角色菜单权限和数据权限等。
- 手册应在开头声明“不同角色可见菜单和按钮可能不同”；缺少按钮时先确认权限，不应让用户通过地址栏绕过菜单。

### 4.4 退出登录

管理平台右上角头像/用户名下拉菜单包含个人中心、项目文档、锁定屏幕和退出登录。

退出步骤：

1. 点击右上角头像或用户名。
2. 点击“退出登录”。
3. 在警告确认框中确认。
4. 系统清除当前页签并返回登录页。

临时离开但仍需保留会话时，可使用“锁定屏幕”；离开共用设备时必须使用“退出登录”。

## 5. 管理平台项目业务功能

### 5.1 管理首页

首页展示四组业务指标及对应趋势：

- 当天活跃人数、当天登录总次数及登录趋势。
- 当天注册数、注册总数及注册趋势。
- 当天知识图谱调用数、知识图谱总调用数及调用趋势。
- 学员当天答题数、答题总数及答题趋势。

页面支持选择日期范围、刷新数据，并展示四个趋势图。手册应说明统计数据来自后台实时汇总，日期范围影响趋势图，不应把截图中的具体数字作为固定示例结论。

### 5.2 企业审核

用途：查看企业注册申请、资质材料，维护审核通过或驳回结果及原因。

建议操作路径：

1. 进入“企业审核”，使用列表条件定位企业申请。
2. 打开详情，核对企业信息和资质材料。
3. 选择“通过”或“驳回”。
4. 在审核对话框中确认审核结论；驳回时填写可追溯的审核原因。
5. 提交后等待“审核处理成功”，再确认列表状态刷新。

审核通过写入状态 `2`，驳回写入状态 `3`。审核会直接影响企业后续使用，应由具备审核职责的角色操作。

### 5.3 学员加入审核

用途：管理学员申请加入企业的记录。

建议操作路径与企业审核相同，但审核对象为学员与企业的绑定关系。通过与拒绝后页面显示“审核处理成功”并刷新列表。后台管理审核与教员 App 审核处理的是同一类真实业务关系，操作前必须核对学员、企业和当前状态，避免重复或相互覆盖。

### 5.4 练习与自测

| 模块 | 主要能力 | 关键关系/限制 |
| --- | --- | --- |
| 练习分类管理 | 维护一级分类、领域、排序、启停状态 | 删除或停用可能影响题目入口 |
| 练习题目管理 | 维护题干、题型、分值、解析和状态 | 可进入“配置可选项”维护答案选项 |
| 练习记录 | 查看学员得分、正确数、错误数 | 可查看答题明细，主要为只读核对 |
| 错题管理 | 按答题明细查看错题、答案和正确性 | 用于排查题目质量和学员薄弱项 |
| 自测题库管理 | 维护自测题型、题干、状态 | 可维护自测答案 |
| 自测结果管理 | 查看用户自测结果、方向建议和 AI 报告 | 主要为只读核对，不应随意修改历史结果 |

新增或编辑题目后，应核对题型、题干、分值、解析、选项及正确答案是否一致。删除分类、题目或答案前必须确认引用关系；手册应将删除列为高风险操作。

### 5.5 岗位与采集

| 模块 | 主要能力 |
| --- | --- |
| 岗位管理 | 维护岗位名称、企业、来源平台、薪资范围、工作地点、发布时间和状态 |
| 采集配置 | 维护招聘信息采集任务；飞书目录任务可查看文档、AI 解析和入库审计 |
| 采集任务实例 | 查看每次任务执行实例、采集数量和合入状态 |
| 采集岗位实例 | 查看采集得到的原始岗位明细 |
| 飞书文档采集页 | 按关键字、目录、状态筛选，查看采集概览和本次岗位明细 |

“立即采集”的代码前置条件：

1. 只有当前配置满足可采集条件时按钮才生效。
2. 新建配置必须先保存并取得 ID；未保存时页面提示“请先保存采集配置”。
3. 触发成功后提示“已触发立即采集”并刷新列表。

立即采集会启动真实外部采集和后续解析/入库链路。操作前应核对采集渠道、目录/关键字、采集数量规则和任务状态；触发后应到任务实例和审计明细核对结果，不得连续重复点击。

### 5.6 协议管理

用途：维护用户协议、隐私协议等协议主数据及富文本版本。

建议操作路径：

1. 进入协议主数据，定位需要维护的协议。
2. 打开“版本管理”，新增或编辑协议内容。
3. 保存草稿并由相关责任人复核协议类型、版本号和正文。
4. 点击发布时，页面出现“确认发布该协议版本？”二次确认。
5. 确认后等待“发布成功”，再核对发布状态。

发布会改变 App 对用户展示的正式协议版本，属于高风险业务操作。发布前必须经过业务/法务审核；错误版本不得通过直接覆盖方式掩盖，应按正式版本治理流程处理。

### 5.7 知识库与智能体

知识库管理支持维护知识库、条目数量和启停状态，并进入知识条目维护内容。独立知识库测试页支持搜索、状态过滤、启停、发送测试问题和查看返回结果。

智能体管理支持维护智能体、关联知识库、提示词配置、回复策略和状态，并提供 QwenPaw 同步及调用测试。

QwenPaw 同步具有明确二次确认：“确认从 QwenPaw 工作区同步智能体？”。成功后页面报告总数、新增数、更新数、删除数和跳过数。同步结果可能包含删除，不能把它当成无副作用的刷新操作；执行前应备份/导出当前配置并确认工作区来源正确。

调用测试建议只使用不含个人信息、企业机密和生产敏感数据的测试问题，并核对智能体、知识库、提示词和回复策略是否符合预期。

### 5.8 客服会话

管理平台“客服会话”用于查看用户或企业端客服会话，并进入“会话消息”查看或发送消息。页面支持客服媒体上传和消息发送接口。

手册应要求操作人员：

1. 先核对会话对象和历史消息，再发送回复。
2. 不发送与业务无关或包含无授权隐私的信息。
3. 图片/视频上传前确认内容、文件大小和对象。
4. 发送失败时先确认会话状态，避免重复发送。

## 6. 管理平台系统管理功能

以下页面代码已确认存在，但最终可见性取决于动态菜单和按钮权限：

### 6.1 租户管理

支持搜索、新增、编辑、启停、导出和删除等操作。租户启停或删除会影响整租户用户访问，必须由平台级管理员执行，并在变更前确认影响范围和备份数据。

### 6.2 部门管理

支持按组织树维护部门，执行新增、编辑和删除。部门是用户、岗位和数据权限的重要归属，删除或调整上级部门前应核对下级部门和关联用户。

### 6.3 用户管理

支持搜索、新增、编辑、导入、导出、删除、重置密码和分配角色等操作。批量导入、删除、重置密码和角色分配均为高风险操作；导入前先下载模板并使用小批量验证，重置密码后通过安全渠道通知本人。

### 6.4 角色管理

支持新增、编辑、导出、删除、分配菜单权限和分配数据权限。菜单权限决定可进入的功能，数据权限决定可查看或处理的数据范围。修改后必须使用对应角色的测试账号验证，不能只用超级管理员账号判断是否生效。

### 6.5 菜单管理

支持维护菜单、按钮和权限标识。错误修改可能导致入口消失、按钮误放开或前端路由异常。修改前应导出/记录现状，新增权限标识时与后端授权规则保持一致，完成后用最小权限账号回归。

## 7. 权限边界与高风险操作

### 7.1 已确认的权限实现

- 标准系统页面大量按钮使用 `v-hasPermi` 做前端权限控制。
- 登录后动态菜单来自 `/system/auth/get-permission-info`。
- 项目自有通用资源接口位于后端 `YjAdminController`，基础路径为 `/yj`，提供资源列表、分页、详情、新增、更新和删除接口。
- 通用资源名由 `YjAdminTableRegistry` 白名单限制，不能访问任意数据库表。

### 7.2 需要重点提示的风险

当前 `YjAdminController` 的通用 CRUD、QwenPaw 同步与调用方法未见 `@PreAuthorize` 细粒度权限注解。也就是说，菜单隐藏或按钮隐藏不能自动等同于后端完成了资源级授权。虽然接口要求后台认证且资源受白名单限制，仍建议后续安全整改补齐后端细粒度权限校验。

操作手册必须禁止以下行为：

- 通过浏览器地址栏、开发者工具或手工接口绕过不可见菜单/按钮。
- 借用超级管理员账号完成日常业务操作。
- 在不清楚影响范围时执行删除、启停、审核、发布、立即采集或同步。

### 7.3 高风险操作清单

以下操作应在手册中使用醒目的“风险提示/注意事项”，并要求二次确认、最小权限、必要备份和操作后核验：

- 企业审核、学员加入审核。
- 删除练习分类、题目、选项、岗位、采集配置、协议版本、知识条目或智能体。
- 启停练习分类、题目、知识库、智能体、租户、用户等资源。
- 协议版本发布。
- 立即采集、QwenPaw 智能体同步。
- 用户批量导入、删除、密码重置、角色分配。
- 角色菜单权限、数据权限分配。
- 菜单、租户、部门、角色删除或结构调整。
