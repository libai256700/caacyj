> 本文档是当前零散任务推进的唯一正式计划入口。正式验收标准统一维护在 `01-验收标准.md`。

- 任务ID：`T0015`

- 合并状态：`不涉及独立分支合并`
- 分支处置：`不涉及独立分支删除`

## 2. 任务目标

1. 以项目真实代码、路由、权限配置和可运行页面为依据，梳理学员端、企业端、教员端、管理平台的完整功能范围与操作链路。
2. 在 `code/develop/操作手册/` 交付四份角色分册，每份同时提供可维护的 Markdown 源稿与正式 DOCX，关键操作配真实页面截图，内容可直接用于培训、上手和日常查阅。

## 3. 任务范围

- 包含：项目结构与运行入口盘点；四端菜单、页面、权限与主要业务流程梳理；本地可运行页面启动；基于真实页面采集截图；四份中文操作手册编写；DOCX 生成、逐页渲染检查；独立验收；Git 提交与远程推送。
- 不包含：修改现有业务功能；伪造账号、数据或未实际存在的页面；操作生产数据库；未经批准修改 `uni_modules/**`；代替用户完成最终人工审核。

## 4. 统一原则

- 事实优先：页面、入口、操作步骤和权限说明必须能从真实代码、正式配置或实际运行页面得到证据；无法验证的内容明确标注前置条件或限制，不作猜测。
- 角色隔离：学员端、企业端、教员端、管理平台分别成册，避免跨角色混写；公共登录、账号与异常处理可按角色分别说明。
- 截图可追溯：优先使用 Chrome DevTools MCP；若当前环境未提供该能力，按 AGENTS.md 规则使用 Playwright 作为网页测试与截图通道，并在验收记录中说明。
- 文档可维护：Markdown 为内容源稿，DOCX 为正式交付件；两者章节结构与关键步骤一致。
- 文档质量：采用 `compact_reference_guide` 设计预设与 `editorial_cover` 首页结构；每份 DOCX 必须渲染为 PNG 并逐页检查，无裁切、重叠、乱码、缺图或错误分页。
- 门禁：`01-验收标准.md` 收口前不开始实施；实施与独立验收由不同子代理执行；正式验收通过后进入待用户审核，不提前归档。
