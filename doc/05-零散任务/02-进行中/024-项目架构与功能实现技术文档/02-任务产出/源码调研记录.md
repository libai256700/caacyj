## 1. 调研范围与方法

### 1.1 范围

- 客户端：`code/develop/yunjikeji`，包括 uni-app 页面、状态、服务封装及 UniCloud 函数。
- 管理端：`code/develop/yunjikeji-admin-ui`，包括鉴权、动态路由、资源配置和专项页面。
- 主后端：`code/develop/yunjikeji-admin-server`，包括启动装配、业务 controller/service/dal、SQL、配置与测试。
- 展示资产：`code/develop/guanwang-site`、`code/develop/xiaoji-site`。
- 测试资产：`tests/mobile-e2e` 及上述工程内与当前功能直接相关的测试。
- 排除项：不读取或修改 `uni_modules/**`；不执行部署、数据库写操作或线上请求；不把 README、历史文档或页面文案置于源码事实之上。

### 1.2 方法

1. 先从构建清单、启动类和页面注册表建立工程矩阵，再沿“页面/请求 -> controller -> service -> 数据或外部依赖”复核关键链路。
2. 引用统一使用仓库相对路径与 1 基行号；配置只记录结构和来源，不复制敏感值。
3. `Fact` 表示允许范围源码直接证明；`Inference` 表示多项证据共同支持但缺少运行态证明；`Unknown` 表示当前仓库无法确认。
4. 当前版本相对旧文档基线已有 11 个提交、25 个文件变化；本轮重新核对引用，不沿用已漂移行号。

### 1.3 总体结论

- `Fact`：允许范围由 uni-app 客户端、Vue 管理端、Spring Boot 模块化单体、UniCloud 函数、两个静态站点及相关测试组成。
- `Fact`：移动端存在两组 API 基址与开发代理（`code/develop/yunjikeji/src/services/apiBase.ts:7`、`code/develop/yunjikeji/src/services/apiBase.ts:27`、`code/develop/yunjikeji/vite.config.ts:32`、`code/develop/yunjikeji/vite.config.ts:43`）。
- `Unknown`：第一 API 请求面的服务实现、生产代理目标和数据主权；不能仅按 URL 前缀映射到某个工程。
